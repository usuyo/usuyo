# 002 — 把平台接进来：登录、列出你存过的、导入

状态：done（2026-11-11。这份写给实现的模型和以后查，不等用户批，见 [CLAUDE.md](../../CLAUDE.md) 开发流程）。验收里要真实登录、对真实平台才能核对的几条（要登录的那几步、真实的封挡），只有用户自己能核对，没有在真实平台上跑过
关联：[PRD 7.1–7.3](../PRD.md#7-功能) · [插件协议 §2、§3、§5、§6](../plugin-protocol.md) · [调研 15](../research/15-fetch-design-xhs-sph-bili.md) · [feature 001](001-m0-core-loop.md)

<a id="目标"></a>
## 目标

用户能拿自己在小红书、微信视频号、B 站存过的东西来试：装上这三个插件，需要登录的在应用里登录一次，列出自己存过的，看一眼再导入，按慢的节奏取回来。

三个插件已经写好，在仓库旁边的 `usuyo-fetch/` 下，各自一个仓库。这里做的是应用这一边。

<a id="范围"></a>
## 范围

<a id="做"></a>
### 做

- **插件登记**：列出装了哪些插件，各自的档位和登录要求（只是标签，不拦）、登录状态、有没有被暂停；能「现在再试」，能「先别试」。
- **凭据**（[协议 §6](../plugin-protocol.md#6-凭据)）：登录得到的 cookie 存系统钥匙串；每次调用只把这个插件声明过的那个站点的交给它，放在这次调用的临时文件里，用完删掉；不进日志，不进资料库。插件设置里标了 `secret` 的同样处理。
- **登录窗口**：壳开一个只装那个站点的网页窗口，和别的站点的数据分开；看到登录成功的 cookie 就读出来交给内核，关窗口。访客身份（站点给任何没登录的访客的 cookie，不是账号）在插件清单的 `visitors` 里声明，用同一套窗口但不登录，网页数据和存进钥匙串的键（`visitor:<站点>`）都和同一主机的账号分开，页面自己生成的 cookie 稳定了就读出来交给内核。
- **列出和导入**：读插件的 `sources`，一页页 `list`；先给预览（新的、已经有的、在回收站里的），用户确认时可以整组选「新的收不收」「回收站里的收不收」，再逐条改（只交和自己那组选得不一样的条目），回收站里的收下就是拿回来；确认后按插件声明的节奏排进任务，能停、能续。手动收下的排在导入前面，只守间隔，不计入每天的批量次数。不出进度条式的催促，只说到哪了。
- **交进来的清单**：本机接口加 `/v1/ping`、`/v1/deliver` 和 `/v1/batches`，和窗口用的路由在同一个监听口。给扩展和脚本单独发令牌（`<id>.<秘密>`，导入页里发、可撤销）；它们先照 [握手](../../apps/desktop/README.md) 确认对面是 usuyo 再发令牌，握手时带上令牌的 id，证明用整个令牌算。交来的清单走同一个预览。小红书的油猴脚本现在握手后把记下的收藏、赞过用 `POST /v1/batches` 交进来，见 [usuyo-fetch/xiaohongshu/README.md](../../../usuyo-fetch/xiaohongshu/README.md#油猴脚本)。
- **手机分享**：监听按机器目录里的 `inbox/`，里面放进来的 `.txt` 链接照收，收完移到 `.usuyo-done/`，没收成的移到 `.usuyo-failed/`（[SPEC §1.1](../SPEC.md#11-目录树)）。
- **开发时装插件**：一条命令把旁边三个插件编出来、装进按机器目录。
- **界面**：照画布的「获取插件」「导入」两页做；条目页和地图不用改。

<a id="不做"></a>
### 不做

- 跟着收（定时自己去看有没有新的）：003 以后。
- 评论、弹幕、点赞列表。
- 视频号的 Hook 那条路。
- 插件的沙箱、签名校验、从网上安装：协议 [§7](../plugin-protocol.md#7-权限与隔离)、[§8](../plugin-protocol.md#8-打包发布与分发)，另做。

<a id="接口"></a>
## 接口

内核的路由和类型加在 `apps/desktop/web/src/api/endpoints.ts`（唯一的契约文件），样例库跟着补。做出来的路由、谁能调什么、`Origin` 和 `Host` 的规则、导入的状态和确认的请求体、事件、节奏和暂停，都写在 [SPEC 本机接口](../SPEC.md#本机接口第-2-层11-11-照代码)；按机器的目录和钥匙串的键在 [SPEC §1.1](../SPEC.md#11-目录树)。

<a id="验收"></a>
## 验收

1. 装好三个插件，「获取插件」页列出它们和各自的标签。
2. 在 B 站的登录窗口扫码登录后，能列出自己的收藏夹；选一个，预览里分出新的和已有的；确认后一条条取回来，间隔照插件声明的节奏。
3. 贴一条小红书笔记链接、一条视频号分享链接，各自落到地图上；取不到的部分如实写原因。
4. 小红书的访客身份取到以后，再取同一条能拿到正文和图。
5. 一个插件被平台挡住：这个插件停下，别的照常；页面上写明原因和什么时候再试。
6. 钥匙串以外的任何文件、日志里都找不到 cookie 的值。
7. `just check` 和前端的检查都过。

[验收](#验收)里要登录的那几步只有用户自己能验，给用户一张短清单。

<a id="测试"></a>
## 测试

- 凭据：只交声明过的站点；调用结束临时文件不在；日志里没有值。
- 列出和导入：用假插件测翻页、已有的不重复、暂停和续上、节奏。
- 交进来的清单：没握手不收，令牌只能交不能读。
