# ADR-004 内核换成 Rust，壳换成 Tauri 2

日期：2026-11-11 · 状态：accepted · 取代 [ADR-001](ADR-001-stack.md)

<a id="背景"></a>
## 背景

2026-11-11 用户说：「我感觉这个底层很大，可能兼具安全性和兼容性和拓展性和易维护性的就真只有rust了」，又说以后要往里放各种转换、各个领域的调用、personal agent 和 computer use，「我们底层其实很重要」。同一天用户把技术栈和桌面架构交给文档会话全权决定（[回答表](../answers.md)）。

[调研 12](../research/12-shell-and-core-language.md#0-结论) 11-04 的推荐本来就是 Rust 内核加 Tauri 2，当时用户选了 Go 加 MyGo。这次改回调研的推荐。

<a id="决定"></a>
## 决定

- 内核、命令行、MCP 服务、守护进程用 Rust，一个 cargo 工作区，代码在 `crates/`。
- 桌面壳用 Tauri 2，只做窗口、托盘、快捷键、登录用的网页窗口这些壳的事。守护进程是独立进程，壳启动它；窗口关了，命令行和 Agent 照样能用。
- 前端照 [ADR-002](ADR-002-frontend-stack.md#和内核的接口) 不变：只经本机 HTTP 和事件找内核，不用壳生成的绑定。
- 全文索引用 tantivy，可以重建；每台机器自己的状态用 SQLite。
- 获取、转换、导出插件照旧是独立进程，用什么语言写都行。
- 内核保持小：只管资料库、索引、任务、插件调度和接口。获取、转换、分析、导出、Agent、以后的 computer use，都经协议接进来，能单独换。

<a id="理由"></a>
## 理由

1. 代码由模型写，没有人逐行看。Rust 的编译器会拦下空值、漏处理的错误、数据竞争这几类问题，等于第一道审查。大改以后能编译通过，多半就还能跑，适合以后反复重写。
2. 壳的成熟度。MyGo 2026-09 才建、只有一个维护者；Tauri 2 用的人多，壳要的能力都有现成的。
3. 检索、向量、小模型可以放进同一个进程，不用每样都另起一个进程。
4. 现在换最便宜：Go 代码只有 794 行，大半是占位。
5. ADR-001 当初放弃 Rust 的理由是「单人速度不占优」。代码改由模型写以后，这条不成立。

<a id="代价"></a>
## 代价

- 编译比 Go 慢。改一行要等超过约 10 秒时，先拆 crate、换链接器；还不行再回头评估（[调研 12 §5](../research/12-shell-and-core-language.md#5-什么会改变推荐)）。
- 依赖多，升级和审计的工作多一些。
- Tauri 3 在路上，以后要迁一次。
