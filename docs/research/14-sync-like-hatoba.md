<a id="0-结论"></a>
## 0. 结论

1. **骨架照搬 Hatoba**：你自己的 Cloudflare 账号里一个 Worker 加一个 D1，没有本产品的服务器。设备上先加密再上传；全库递增的 `seq` 当变更流，每条记录一个版本号做比较并交换（CAS）；冲突在客户端解密后判（[§1](#1-hatoba-怎么做)）。
2. **多一个 R2 桶放大文件**：D1 放记录（一个条目一条）和全部文字；网页原样和媒体切成 8 MiB 的块放 R2。文件按内容寻址，同一份只传一次（[§3](#3-存在哪和花多少)，建议）。
3. **和 Hatoba 最大的不同：本机不加密**。资料库在本机是明文，Obsidian 能直接打开；只加密离开本机的。会话令牌和库钥匙放系统钥匙串，主密码不落盘（[§4](#4-加密)，建议）。
4. **冲突按层分**：原样只增，不冲突；机器写的按规则合并，不打扰你；你写的字做三方合并，合不上两份都留，进「两边都改过的」。底本和输掉的那份本机也留一份（[§5](#5-改动和冲突)，建议）。
5. **撤销设备就是删会话**，和 Hatoba 一样：挡住它以后的同步，挡不住知道主密码的人，管不到那台已有的明文。改主密码要带旧密码，R2 加 30 天桶锁，偷到会话的人改不了密码、删不掉块（[§6](#6-设备)，建议）。
6. **钱不是问题，额度是**：1 万条、200 GB 媒体，免费版只付 R2，每月约 2.93 美元。卡住的是每天 10 万次 Worker 请求和 10 万行 D1 写入：第一次上传按两天排，新设备全部下载另要约 1.5 天；Workers Paid（每月至少 5 美元）没有按天的上限（[§3](#3-存在哪和花多少)）。
7. **先文字，后媒体**：S0 定格式，S1 只同步文字，S2 媒体，S3 换钥匙和整轮撤销，S4 WebDAV、S3、文件夹。照你说的「先开发主要功能」排（[§2](#2-本产品要同步什么)，建议）。
8. **资料库格式先改四处，后端做成内核接口**：记录 id 和目录名由身份算、`manifest.jobs` 移出、改动记录按设备分段、按机器的状态搬出资料库目录，这四处挡资料库 v1。Cloudflare、WebDAV、S3、文件夹都实现内核里一个只经手密文的 `Remote` 接口，不做成插件（[§2](#2-本产品要同步什么)、[§7](#7-以后的后端)，建议）。

<a id="1-hatoba-怎么做"></a>
## 1. Hatoba 怎么做

- **部署**：同步可选，跑在你部署进自己账号的一个 Worker 和一个 D1 上，「the free plan usually covers personal use」，没写具体数（仓库根 `README.md:118-121`）。三条路：应用里贴 API token 自动部署（推荐）、Deploy to Cloudflare 按钮、wrangler（`W/README.md:13-15`）；token 要 Workers Scripts Edit 和 D1 Edit（规格:774-787）。
- **密钥**：主密码经 Argon2id（m=64 MiB、t=3、p=4）得 `master_key`，HKDF 分出 `enc_key`（只在本机）和 `auth_key`（登录时发给 Worker，Worker 只存 SHA-256）。随机的 `vault_key` 加密每个条目，被 `enc_key` 和恢复码各包一份存在云端；改主密码只重包（规格:151-171）。
- **信封**：`{v, n, c}`，AES-256-GCM，每次新的 12 字节 nonce，AAD 绑条目 id，类型在密文里（规格:175-181）。
- **服务器看得到**：条目数、id、密文大小、修改时间、设备数、登录和同步时间、IP（规格:226）。被改过的 Worker 解不了密，但能删、能回滚、能拒绝服务（规格:205）。
- **变更流**：按 `seq` 增量拉，`seq` 全库递增、允许空洞；游标只从拉到的号前进（`C/sync/engine.rs:23-25`）。推送带 `base_revision`，Worker 跑 `UPDATE … WHERE revision = ?`，零行就退回服务器那行当冲突（`W/src/routes/items.ts:142-178`）。删除是墓碑，一直留（规格:712）。每 60 秒、改动后 2 秒等时候跑一轮（规格:689）。
- **冲突**：两边解密后比明文里的 `updated_at`，后写的赢，相等时远端赢；一删一改，改的赢；只有 SSH 密钥留冲突副本（`C/sync/conflict.rs:133-157`）。自动解决都写进本机 `conflict_log`，两边信封都存（`C/store.rs:155-167`），可逐条恢复另一版（规格:708）。时钟偏差没处理（grep `skew|clock` 只有测试代码）。
- **设备**：一台设备就是一个会话，30 天，用一次往后滑（`W/src/config.ts:11-12`）。撤销就是删会话，被撤销的设备输对主密码马上能回来，测试里专门有这条（`W/test/devices.test.ts:87-92`）。改主密码不要旧密码（规格:209）。
- **不同步**：任何文件，同步单位是不超过 64 KB 的信封（`W/src/config.ts:19`）；设备本地状态和偏好（规格:471-493）。

免费版上两处会撞线（推断，没实测）：每条改动一个 `db.batch`（`W/src/routes/items.ts:184-192`），推 100 条是 100 多次查询，而 [D1 限额](https://developers.cloudflare.com/d1/platform/limits/)写免费版每次调用 50 次、batch 算一次，超了报错；会话满 60 秒就续期写一次 D1（`W/src/middleware.ts:85-89`），每台每天约 1,440 次。

<a id="2-本产品要同步什么"></a>
## 2. 本产品要同步什么

建议：

| 路径 | 层 | 哪段 |
|---|---|---|
| `items/…/manifest.json` | 混合，按字段合并 | S1 |
| `content.md`、`derived/` 下的文字 | 原样、机器 | S1 |
| `notes.md`、`topics/`、`cards/`、`canvas.json` | 你写的 | S1 |
| 改动记录、改动提议（逐个存成文件，[overview §8](../discussion.md#14-资料库能不能放进同步盘)）、删除记录、资料库设置 | 元数据 | S1 |
| 网页原样，`images/`、`media/`、关键帧（没下视频的设备算不出来） | 原样、机器 | S2，放 R2 |
| `derived/embeddings.bin` | 机器，跟着模型走 | 不同步 |
| `.trash/` | — | 只同步「在回收站」，每台各挪各的 |

**留在每台机器上的**：索引、`jobs.db`、缓存、`sync.db`（`device_id`、游标、上次同步的 blob id、冲突记录、底本）、导出记录。放系统应用数据目录，按库 id 分开，如 `~/Library/Application Support/{Name}/libraries/<库 id>/`；不放 `.{name}/local/`，资料库进同步盘时会被带走。Hatoba 同理不进漫游目录（规格:483）。

**设置**：回收站天数、转换做哪几层、主题和关键词、跟着收、Agent 能看的范围跟着资料库；外观、插件和插件密钥（[ADR-003 §4](../decisions/ADR-003-plugins.md#4-权限与隔离)）、模型端点和密钥、导出路径每台各管。新设备第一次拉完之前不写设置（规格:728）。

**回答 [PRD 7.10](../PRD.md#710-存储删除与联网) 留下的**：媒体放 R2；索引和任务库按机器分开，放资料库目录外；同步盘能用，但和内置同步二选一（问题 4），[K6](../open-decisions.md#11-存储同步与联网) C 照旧。[PRD 原则 3](../PRD.md#4-原则) 可加一句：「资料库在本机为真；同步只传加密后的副本，索引和任务状态按机器分开、不同步。」（建议）

**资料库格式先改四处**（S0；SPEC v0 的写法两台同时用会出问题，推断）：

1. **目录名** `<platform>-<id8>-<rand4>` 的 `rand4` 随机（[SPEC §2](../SPEC.md#2-资料库目录真相源)），两台离线各收下同一链接会建出两条，违反 [SPEC §7](../SPEC.md#7-去重)。改成记录 id 由身份的 HMAC 算，`rand4` 换成身份的哈希；跨月收下时路径不同，第一次同步时后建的改名过去。
2. **`manifest.jobs`** 是每台的任务状态，两台会来回改写。移进 `jobs.db`；某层做没做完看 `derived/` 有没有那个文件。
3. **改动记录** `journal/YYYY-MM.jsonl` 两台都追加，一定冲突。改成 `.{name}/journal/<device>/<段号>.jsonl`，封口后不改。
4. **按机器的状态**搬出资料库目录，见上。

**分段**（建议）：S1 是网页原样和媒体以外的一切，加部署、设备和「两边都改过的」最小版；S2 切块、用到再下、清理；S3 钥匙分代、整轮撤销、补齐长度。

<a id="3-存在哪和花多少"></a>
## 3. 存在哪和花多少

**放法**（建议）：

| 放在哪 | 存什么 | 规则 |
|---|---|---|
| D1 `records` | 一个条目一条，内容是加密的文件表（路径 → blob id、大小、层）；主题页、卡片、设置、每条删除记录、每个提议、每段改动记录也各一条 | 照 Hatoba 的 `items` 表；信封上限 64 KB；一页拉 500 条 |
| D1 `blobs` | 文字层的文件，不论大小；压缩加密后超过 16 KiB 的切成几行 | 按内容寻址，只插不改 |
| R2 | 网页原样、原图、视频、关键帧 | 8 MiB 一块一个对象，键 `b/<blob id>/<块号>`，只建不覆盖 |

- **文字不论大小都进 D1**：长文章、一小时的口播压缩后也会超过 16 KiB，按大小分就有文字只留本机；多几十 MB（推断）。
- **一页 500 条**：D1 单次结果最多 50 MB，2026-11-04 起生效（[公告](https://developers.cloudflare.com/changelog/post/2026-10-30-query-result-size-limit/)），1,000 × 64 KB 会超。
- **一次推送一个 batch**：batch 对 50 次的上限只算一次（D1 限额）。batch 是事务，一条失败整批回滚（[D1 查询开销](https://developers.cloudflare.com/d1/observability/find-expensive-queries/)），所以先校验完整个请求；`seq` 在 batch 里用子查询算，免得两台拿到同一段号（推断）。
- **R2 的块**：不用分片上传；`put()` 带客户端算的 `sha256`，传错的块进不去（[R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)）。同一键每秒最多写一次，再快回 429（[R2 限额](https://developers.cloudflare.com/r2/platform/limits/)），客户端当「再问一次有没有」。
- **先经 Worker 转发**：预签名网址能少两个数量级的 Worker 请求（推断），但 Worker 里要放 R2 的 S3 密钥（[R2 预签名](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)），S2 时再比。

| 项 | 免费版 | Workers Paid |
|---|---|---|
| 订阅 | 0 | 每月至少 5 美元 |
| Worker 请求 | 每天 10 万次 | 每月 1,000 万次含在内，超出每百万 0.30 美元 |
| Worker CPU | 每次 10 ms；解析大请求体通常要 10–20 ms | 默认 30 秒 |
| D1 每次调用的查询 | 50 | 1,000 |
| D1 写 | 每天 10 万行 | 每月 5,000 万行含在内 |
| D1 单库 | 500 MB | 10 GB，不能再加 |
| D1 时间回溯 | 7 天 | 30 天 |
| R2 | 每月 10 GB、A 类 100 万次、B 类 1,000 万次免费，出流量不收费；超出每 GB 每月 0.015 美元 | 同左，不论 Workers 套餐 |

出处：[Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)、[Workers 限额](https://developers.cloudflare.com/workers/platform/limits/)、[D1 定价](https://developers.cloudflare.com/d1/platform/pricing/)、[R2 定价](https://developers.cloudflare.com/r2/pricing/)。额度 UTC 0 点重置；超了 Worker 回 1027、D1 报错，客户端就停到那时，不按指数退避重试。

**估算**（推断）：1 万条，4,000 条视频平均 49 MB，3,000 条图文每条 4 张 300 KB，3,000 条文章，每个视频 20 张 60 KB 的关键帧，媒体约 205 GB。

| 项 | 量 | 免费版 |
|---|---|---|
| R2 存储 | 约 205 GB | (205 − 10) × 0.015 ≈ 每月 2.93 美元 |
| 第一次上传的 Worker 请求 | 约 12 万次 | 按每天八成排，约 1.5 天 |
| D1 第一次写入 | 8.8 万到 14.9 万行（主键索引、`seq` 索引都算） | 可能一天写不完，按两天排 |
| 新设备全部下载 | 约 11.9 万次 Worker 请求 | 又约 1.5 天；「用到再下」只要几百次 |
| 平时 | 两台每 60 秒一轮，每天最多约 2,880 次 | 约 3% |
| 上传时间 | 205 GB | 50 Mbps 约 9 小时，跨境可能慢得多 |
| 每月 | | 约 2.93 美元；开 Paid 约 7.93 美元 |

- 关键帧 8 万个小对象占请求的三分之二，一个视频的打成一个包最省。R2 低频存储没有免费额度，不用。
- D1 到顶会早于按 125 MB / 1 万条推出的约 4 万条：旧版本、墓碑、改动记录只增。响应带回 `rows_written` 和 `size_after`（D1 定价），到八成提示。

<a id="4-加密"></a>
## 4. 加密

**照 Hatoba 的**：[§1](#1-hatoba-怎么做) 的密钥层级和信封；KDF 参数存成 JSON，客户端设下限防降级；恢复码只显示一次（规格:151-181）。Go 有现成的 `golang.org/x/crypto/argon2`、标准库 `crypto/hkdf` 和 `crypto/cipher`（pkg.go.dev 查）。`hatoba/enc/v1` 一类的域分隔串换成 `{name}/…/v1`（`C/crypto.rs:40-78`）。

**不一样的**（建议）：

| 哪里 | Hatoba | 本产品 |
|---|---|---|
| 本机 | 只存密文 | 明文：文件是真相，Obsidian 要能打开（[PRD 7.9](../PRD.md#79-导出与互通)） |
| 钥匙 | `vault_key` 锁定时清掉 | 会话令牌和库钥匙放系统钥匙串，你不在时也能同步；主密码、`auth_key`、恢复码不落盘 |
| 子钥匙 | 一把 `vault_key` | HKDF 分出记录、文件、id 三把 |
| 记录 id | UUIDv7 明文 | HMAC：目录名里有平台名和年月 |
| 文件 id | 没有文件 | 对内容做带钥 HMAC，免得服务器能确认你有某个公开视频（推断） |
| 大文件 | 没有 | 每个 blob 一把 HKDF 钥匙，块号当 nonce，AAD 带块号和「最后一块」 |
| 改主密码 | 不要旧密码 | 要旧密码算出的 `auth_key`，或恢复码 |
| 回滚 | 检测排在 P2 | 记住见过的最大 `seq`，变小就停；你确认后游标归零重拉 |
| D1 时间列 | 客户端的 `updated_at` | 服务器写入时间，少露编辑时间 |

- **服务器看得到**记录数、HMAC id、密文大小、版本号、blob 大小、上传时间、设备数、IP；**看不到**路径、标题、平台名、正文、你写的字、blob 属于哪条；**推得出**大约多少条、每天收下多少，以及每个视频多大，除非补齐长度（S3 段，约多 17 GB）。
- **KDF 下限**：Hatoba 下限的注释写 p=1，默认和规格写 p=4（`C/crypto.rs:182`、`:240-251`）。p 只是并行通道数，下限 p=1 不让哈希变便宜（推断）；照抄时下限 p=1、默认 p=4，注释写清。

<a id="5-改动和冲突"></a>
## 5. 改动和冲突

**变更流照 Hatoba**，多三条（建议）：

- **先传文件再推记录**，拉到的记录引用的 blob 一定已在服务器上。
- **条目齐了才落盘**：在临时目录里拼好，再整个换进 `items/`。
- **「等文件」表**：缺块时照 Hatoba 游标停住，下一轮报「游标没动」（`C/sync/engine.rs:227`），同步卡死。改成游标照常前进，缺文件的条目记进 `sync.db` 定时重试，同步页写明缺什么。

**发现本机改动**：主题页能在 Obsidian 里改（[PRD 7.7](../PRD.md#77-你写的那一层)），所以 `topics/`、`cards/`、`notes.md` 用文件监听，加启动时和每小时按大小、修改时间扫一遍。`raw/` 被改了不上传，报「原样被改过」（[原则 2](../PRD.md#4-原则)）。

**按层合并**（建议）：

| 层 | 例子 | 规则 | 出卡片 |
|---|---|---|---|
| 原样 | `raw/`、`content.md`、媒体 | 只增；同一路径内容不同只会是出错，两份都留 | 只在出错时 |
| 机器写的 | `derived/`、关键帧；manifest 的快照、身份、完整度 | 快照和身份取并集；完整度只升不降；`derived/` 新的留下 | 不出 |
| 你写的 | `notes.md`、主题页、卡片、`tags.user`、私密开关、画布位置 | 按行三方合并；改到同一处，新的当现在这份，另一份留着；不往文件里插冲突标记 | 出 |
| 元数据 | 设置、删除记录、提议、改动记录分段 | 设置按字段合并；删除记录取并集；提议状态只往前走；每段只有一台写 | 同一项设置两边改时出 |

Hatoba 一律后写先赢，只给 SSH 密钥留副本；本产品你写的字都照 SSH 密钥对待。

- **底本和输掉的那份本机也留**：云端没人引用的 blob 30 天后清理，离线久的设备就没底本了。照 `conflict_log`，`sync.db` 存你写的那层上次同步的文本和输掉的文本；丢了就两份都留。
- **Obsidian 同时在改**：写回前再比一次修改时间和哈希，变了就重新合并；先写临时文件再改名。
- **时钟**：`updated_at` 取本机时间和「见过的最大远端时间加 1 毫秒」中大的，但要有上限，否则一台钟设到 2030 年的设备会把所有设备拖走。Worker 每个响应带服务器时间，差超过 5 分钟就提示、不推；回收站到期、清理期限按服务器时间。

**删掉和回收站**（K1 A 已定，[PRD 7.10](../PRD.md#710-存储删除与联网)；同步里的做法是建议）：

- A 删掉：manifest 写「在回收站」和时间，B 挪进自己的 `.trash/`，到期照 A 写的算；到期时先清的那台推墓碑、写删除记录。
- A 删了、B 同时改了笔记：回收站赢，B 的改动合进回收站那份，出卡片。和 Hatoba「改的赢」相反，因为回收站不丢东西。已清除、离线的 B 回来时改过它：放进 B 的回收站再留 30 天，出卡片，不悄悄复活。
- 删除记录一个身份一条，id 是身份的 HMAC。
- 「彻底忘掉」：删除记录推墓碑，云端只剩 HMAC id；D1 时间回溯里旧密文还在（免费版 7 天、Paid 30 天），R2 的块等清理，界面写明多久清干净。

**清理没人引用的块**由客户端算：只删上传超过 30 天、两次快照（列块 → 拉全部记录 → 隔至少一天再拉）都没人引用的。否则有竞态：A 问 `has` 得到「有」就不传，C 恰好删了这块，A 再推上引用它的记录。`has` 之后隔几小时才推记录，就重问一次。

**改动记录和提议**：[原则 6](../PRD.md#4-原则) 不受影响，别的设备的改动已在那台确认过，这台直接生效，带着出处。提议也同步，在 B 上只在改动记录页查得到（[product-model §7.3](../product-model.md#73-其他对象)）；两台应用了同一提议，结果一样就收敛。

**「两边都改过的」**按[原则 4](../PRD.md#4-原则) 改 Hatoba 的逐条页面：同步不停；没有角标、数字、弹窗；入口在设置 › 同步，只一行字，如「上周有两处两边都改过，先按较新的留下了」。一条一张卡片，按钮「就这样」「换成另一份」，Markdown 多一个「两份并排」，留 30 天。

<a id="6-设备"></a>
## 6. 设备

**第一台**（建议）：

1. 三种部署照 Hatoba，加 R2。token 要 Workers Scripts Edit、D1 Edit、Workers R2 Storage Edit，绑域名再加 zone 级 Workers Routes Edit（[API 权限](https://developers.cloudflare.com/fundamentals/api/reference/permissions/)）。[Deploy 按钮](https://developers.cloudflare.com/workers/platform/deploy-buttons/)会自动建 D1 和 R2 桶。D1（`--location apac`，`W/README.md:44-99`）和 R2（位置提示 `apac`，[R2 数据位置](https://developers.cloudflare.com/r2/reference/data-location/)）都能放亚太。
2. 健康检查，连不上 workers.dev 就引导绑域名。有人报告「workers.dev/国内是被墙的」（[lesnolie/movecar#9](https://github.com/lesnolie/movecar/issues/9)，2025-12-31，单个报告）。
3. 定主密码，恢复码显示一次；第一次上传按额度排，写清要几天，能暂停。

**第二台**：Worker 地址加主密码，先拉设置和文字。本机已有一份（比如拷过去的目录），照 Hatoba 全当没推过，内容一样不算冲突（规格:737），一样的文件不重传。没下的视频写「在云端，没下载到这台」（[PRD §8](../PRD.md#8-条目的状态)）。

| 动作 | 挡住什么 | 挡不住什么 |
|---|---|---|
| 撤销（删会话） | 它以后的拉和推；不知道主密码登不回来 | 它本机的明文资料库；知道主密码的人 |
| 改主密码（要旧密码，同时撤销别的会话） | 知道旧密码的人 | 已从钥匙串拿到库钥匙、又有你 Cloudflare 账号的人 |
| 开新一代钥匙（S3） | 拿旧钥匙的人读以后的内容 | 旧内容 |

**两条不能照搬**（建议）：

- Hatoba 遇到解不开的远端就保留本机、推上去覆盖（`C/sync/engine.rs:386-398`）。有了钥匙分代，没拿到新钥匙的旧设备会拿旧内容盖掉新的。改成停下，提示重新登录或升级。
- 钥匙分代撞上去重：只换文件钥匙时，新一代算出的 blob id 和旧对象一样，就不传，记录却引用旧钥匙加密的块。文件表每项记下加密的代，或 id 钥匙一起换。

**偷到会话的人能清空媒体**（推断）：Hatoba 的数据接口只要完整会话（`W/src/routes/items.ts:69`、`:180`），删块照写也会这样；R2 没有时间回溯。建议 R2 桶锁按对象年龄让 `b/` 保留 30 天（[R2 桶锁](https://developers.cloudflare.com/r2/buckets/bucket-locks/)），和清理的 30 天对上；或删除时当场输主密码（问题 7）。

**其他**：30 天没开的电脑会话过期，要等你输主密码；被撤销的拿到 401，写「这台被移除了，输主密码重新加入」，不一直重试。丢了一台电脑：在另一台撤销它，拿不准就改主密码，那台上的明文靠磁盘加密。

<a id="7-以后的后端"></a>
## 7. 以后的后端

Hatoba 把后端抽象成 `SyncBackend` trait，Worker 和 D1 直连各实现一份（规格:509-528）。本产品照这个形状写 Go 接口 `Remote`，只经手密文和不透明 id：版本和能力、登录和恢复、拉推记录、文件的有无、写、读、列、删，设备和撤销。`Info` 报能力（有没有服务器端比较并交换、会话、只建不覆盖），引擎据此决定能同步还是只能备份（建议）。

| | Cloudflare（S1） | S3 和兼容的（S4） | WebDAV（S4） | 文件夹（S4） |
|---|---|---|---|---|
| 比较并交换和 `seq` | D1 `UPDATE … WHERE revision = ?` | 每次改动写一个 `log/<seq>` 对象，带 `If-None-Match: *` 抢号 | 同 S3，要服务器认这个头 | 做不了 |
| 撤销 | 删会话 | 换 S3 密钥 | 改 WebDAV 密码 | — |
| 能做 | 同步 | 同步 | 同步；不认条件写就只备份 | 只备份 |

- **依据**：S3 的 `If-None-Match` 防覆盖，回 412（[AWS 条件写](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html)）；`If-None-Match: *` 防止 PUT 覆盖已有资源（[RFC 9110 §13.1.2](https://www.rfc-editor.org/rfc/rfc9110#section-13.1.2)）；WebDAV 靠 ETag 防丢更新（[RFC 4918 §8.6](https://www.rfc-editor.org/rfc/rfc4918#section-8.6)）。坚果云、Nextcloud 认不认没查，设置时先探：同一路径带这个头写两次，第二次应回 412。
- **备份**：PRD 7.10 的「备份到 WebDAV、S3 或另一个文件夹」用同一套格式，里面只有密文。
- **不做成插件**：导出插件拿明文只读视图（[插件协议 §4.4](../plugin-protocol.md#44-导出的-run-与-readback)），同步要双向搬全部文件、比较并交换。做成插件就得把钥匙交给插件（违背[插件协议 §4.3](../plugin-protocol.md#43-模型与密钥由宿主代发)），插件还成了资料库的写方（违背 [ADR-003 §2](../decisions/ADR-003-plugins.md#2-进程与协议)）。这几种是通用协议，没有平台知识，[原则 1](../PRD.md#4-原则) 不挡。以后接专有网盘再开第四类「远端」插件，方法就是 `Remote` 那些。
- **Go 的库**（`gh api` 查，都在维护）：`minio/minio-go`、`emersion/go-webdav`、`zalando/go-keyring`、`klauspost/compress`。

<a id="8-能直接用-hatoba-的什么"></a>
## 8. 能直接用 Hatoba 的什么

MIT 只要求保留版权和许可声明（`LICENSE:12-13`）；FSF 把它（Expat）列为和 GPL 兼容（[FSF 许可证列表](https://www.gnu.org/licenses/license-list.html#Expat)），能并进 AGPL-3.0 的内核（推断，没问法律意见）。Worker 是你部署进自己账号的，建议单独一个目录或仓库，用 MIT。

| 怎么拿 | 什么 |
|---|---|
| 直接拿，改名 | Worker 骨架：`W/src/` 14 个文件 939 行，依赖只有 Hono（`W/package.json:20-22`）。会话、限流、不发 CORS、错误码、登录和设备等路由；升级规则；三种部署和应用内部署的八步（规格:744-878）。信封、KDF 参数、恢复码格式 |
| 直接拿 | 游标规则、`seq` 空洞、`not_found` 后重传、一轮一条最多推两次 |
| 照着改 | `items` 改 `records`，一次推送一个 batch；加 `blobs` 表和 R2 绑定；续期改一小时以上；冲突界面（`apps/desktop/src/features/sync/SyncConflictsView.tsx:50-150`）；Worker 测试（`W/test/` 11 个文件）当规格 |
| 不照搬 | 远端解不开就覆盖；改主密码不要旧密码；时钟没上限；按分钟续期 |
| 自己写 | Go 客户端（Hatoba 的是 Rust）：加密、扫文件、文件表、按层合并、切块续传、清理、钥匙串、S3 和 WebDAV；TypeScript 的同步页 |

要换的名字：服务名 `hatoba-sync`；Worker 识别规则（`DB` 加 `AUTH_LIMITER` 绑定，规格:816），免得把对方的 Worker 认成自己的；全部 `hatoba/*/v1` 串。

<a id="9-待核实清单"></a>
## 9. 待核实清单

1. 免费版转发一个 8 MiB 块、解析多大的请求体会超 10 ms CPU；字节上限先按 512 KB 到 1 MB 试。
2. Hatoba 现在的写法在免费版上推 100 条会不会撞 50 次查询，只差实测。
3. 开通 R2 要不要绑付款方式：[R2 入门](https://developers.cloudflare.com/r2/get-started/)只说先走 checkout。
4. R2 绑定的 `put()` 认不认 `If-None-Match: *`；收流要不要已知长度。
5. D1 的主键索引、`WITHOUT ROWID` 表一次写入各算几行：建表各插 100 行看 `rows_written`。
6. 免费版一次调用能发多少次 R2 `head`，50 还是 1,000；之前 `has` 一次最多问 40 个。
7. R2 桶锁的「年龄」是不是从上传时算起。
8. 从你的网络连 workers.dev、`*.r2.cloudflarestorage.com`、自己的域名，通不通、多快。
9. 坚果云、Nextcloud 认不认 `If-None-Match: *` 和 `If-Match`；坚果云的频率限制。
10. [§3](#3-存在哪和花多少) 的大小假设要拿你真实的一批条目量一次。
11. Hatoba 的 KDF 下限 p=1、默认 p=4，哪个是本意。
12. 三方合并用现成的 Go 库还是自己写 diff3。
