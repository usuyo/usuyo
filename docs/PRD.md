<a id="1-定位"></a>
<a id="1-为什么做"></a>
## 1. 为什么做

**已定**（10-30 定位的意思，[调研 07](research/07-positioning-and-naming.md#1-这是什么东西)；11-02 雾，[open-decisions §1.5](open-decisions.md#15-11-02-回复记下的)）：

- 平台的收藏夹是平台留住你的办法，不是你的东西。帖子会删、会下架、会锁进登录墙。
- 想回头看一条，得回到推荐流里。推荐流、「建议收藏」式的标题、一键 AI 总结，都在替你挑看什么，AI 总结里也混着大量垃圾。
- 收了一大堆以后，不知道从哪下手。你说：「那个雾感觉有点脑雾的那种，因为就是你收藏了一大堆，但是却不知道从何开始去处理」。

本产品把你收下的东西原样存到你自己的电脑上，转成能搜的文字，让你自己的判断留在最上面一层。

**待讨论**（[第 2 条](discussion.md#2-地图上一直清楚的是什么)）：我们的理解是，产品不驱散雾，只给一个进去的口子，从哪一片进都行，其余的留在雾里；不承诺清掉什么。等你确认。

<a id="3-是什么和不是什么"></a>
## 3. 是什么和不是什么

**已定**（11-01，S3，[open-decisions §1.4](open-decisions.md#14-11-01-第二次回复定下的)）。一句话：

> 在推荐流外，维护一套你自己的思路。

被问「这是什么」时接一句：

> 添加获取插件后，你在各平台收下的内容存到自己电脑上，口播和图里的字能搜，回头看不用再进推荐流。

和相近的东西比（[调研 07](research/07-positioning-and-naming.md#11-和相近东西的区别)）：

| 相近的 | 区别 |
|---|---|
| 个人知识库 | 它的单位是你整理过的笔记，没整理的就是欠着的活。本产品的单位是你收下的原样，你的判断另成一层；只收下、不整理也正常。知识库管你知道什么，本产品管你看重什么。你说过：「可以说个人知识库但是实际上也不是」（10-30，[调研 07](research/07-positioning-and-naming.md#1-这是什么东西)） |
| 稍后读 | 它是待读队列，收下就答应以后要读。本产品没有队列，收下不带这个承诺 |
| 书签、平台收藏夹 | 存的是链接，帖子一删就失效；平台收藏夹还是推荐信号。本产品存内容的副本和转出的文字 |
| AI 总结 | 总结是模型替你挑，还常顶替原文。本产品转写是为了能搜；AI 摘要默认关，开了也单独一栏，原样一直在 |

**待讨论**（晚点）：品类词和口号（[S1、S5](open-decisions.md#3-叙事与介绍)）。

<a id="4-原则"></a>
## 4. 原则

1. **内核和官方组织里没有平台获取逻辑。** 自己维护的获取插件放在 `{fetch-org}`。随安装包预装的只有通用网页获取和别的工具导出文件的导入，都不含平台知识。已定（11-01，D-f、P1、P3，[open-decisions §1.1](open-decisions.md#11-十条方向)、[§1.4](open-decisions.md#14-11-01-第二次回复定下的)）。
2. **机器永不改写或删除原样。** 取回来的原样只增不改；转写、识别、AI 产物另放，可以重算。只在你选「只留文字」或「删掉」时移走，先进回收站。已定（10-20，[CLAUDE.md](../CLAUDE.md) 原则 2；11-04 改措辞，K5 A，[open-decisions §1.8](open-decisions.md#18-grill-回答)）。
3. **文件是真相，索引可丢、可重建。** 已定（10-20，[CLAUDE.md](../CLAUDE.md) 原则 3）。
4. **不制造压力。** 没有未读数、待办队列、打卡；整理是可选的，没有「没整理」这种状态。已定（10-20，[CLAUDE.md](../CLAUDE.md) 原则 4）。文案细则见 [product-model](product-model.md#4-文案规则)。
5. **入库内容和插件输出都是不可信输入。** 给 Agent 的内容标明不可信和出处；写操作只收结构化参数；MCP 不给删除和外发。已定（10-20，[CLAUDE.md](../CLAUDE.md) 原则 5；「插件输出」11-03 照[插件协议](plugin-protocol.md#1-概念)补上）。
6. **Agent 和模型的改动先提议，你确认后生效，可以整批撤销。** 已定（10-20，[CLAUDE.md](../CLAUDE.md) 原则 6）。
7. **能换的都能换。** 获取、转换、导出三类插件，还有模型、Agent、存储位置。本机还是云端由你选，离开本机的都标明去向。已定（10-21，v0.3；10-28 三类插件，[ADR-003](decisions/ADR-003-plugins.md#1-插件分三类)）。
8. **只做开源，不商业化，没有云账号。** 内核 AGPL-3.0；插件协议的 schema 和 plugin-kit 用 MIT。已定（11-01，D-i，[open-decisions §1.1](open-decisions.md#11-十条方向)；[ADR-003 修订第 6 条](decisions/ADR-003-plugins.md#修订-2026-11-01)）。上不上报使用数据、插件失效从哪看出来，晚点（[L8](open-decisions.md#4-借鉴其他软件)）。
9. **视觉来自软件本身。** 雾是点阵（圆点或方像素）；文字、连线、卡片、控件用现代界面和真正的排版；不做终端风格的字符界面；变化都和雾走同一个时钟；没有角色或动物。已定（10-28 点阵加现代界面、否掉终端风格，10-29 一个时钟；11-04 「不要角色或者动物」，[open-decisions §1.7](open-decisions.md#17-11-04-回复记下的)）。细节见 [overview 视觉方向](overview.md#9-视觉方向)。

待讨论、会改措辞的：原则 3 加一句同步怎么做（11-04 方向：自己的 Cloudflare 账号，端到端加密，学 Hatoba；细节见[第 14 条](discussion.md#14-资料库能不能放进同步盘)）；原则 4 加不加一句不说清空、进度、处理完（[第 2 条](discussion.md#2-地图上一直清楚的是什么)）；原则 6 Agent 收下算不算例外（[第 15 条](discussion.md#15-agent-能不能直接收下)）；兼容和开创要不要成一条原则（[第 17 条](discussion.md#17-兼容和开创各指什么)）。

<a id="6-主循环和一个例子"></a>
## 6. 主循环和一个例子

收下 → 变成文字 → 回头看（搜到、打开）→ 你写的那一层（记一句、主题页、让一片一直清楚）

- 每一步都可以停，只收下、从不整理是正常用法。已定（10-20，见[原则 4](#4-原则)）。
- 存进来的就留着，不做让它变少的功能。已定（10-28，[product-model](product-model.md) 开头的注）。
- 你写的那一层落在哪，待讨论（[第 3 条](discussion.md#3-知识的单位)）。

例子：周三晚上在抖音刷到一条 4 分钟的手冲咖啡教学。你之前添加过抖音的获取插件。

| 阶段 | 你做了什么 | 看到什么 |
|---|---|---|
| 收下 | 复制分享链接，按全局快捷键，粘贴，回车 | 浮层写「收下了」，一秒后消失 |
| 获取 | 不用做什么 | 这条从「只有链接」变成封面和标题 |
| 变成文字 | 不用做什么；默认等接上电源、电脑空闲时做 | 条目页多出「口播文字」「画面」两栏 |
| 找回 | 两个月后搜「水温 92」 | 结果写「口播 01:42」，点开从那一秒播 |
| 记一句 | 看完点「记一句」，写「92 度，闷蒸 30 秒」 | 条目上出现这句话 |
| 汇总（待讨论，[第 3 条](discussion.md#3-知识的单位)） | 搜「手冲」，全选 23 条，放进新主题，点「起草这一页」 | 草稿每段标着出自哪几条，你逐段接受 |

结果：23 条都还在，多了一页你的话；要回到原话，引用里就有。

## 7. 功能

### 7.1 收下

**已定**（10-21，v0.3；11-03 投递，[插件协议](plugin-protocol.md#5-投递接口)；10-23 扩展权限，[product-model](product-model.md#11-参考看看收藏)）：

- 入口：粘贴、拖入、全局快捷键、浏览器扩展「保存当前页」、命令行、本机接口、投递（扩展、油猴脚本、手机快捷指令）、监听文件夹。
- 一瞬间落成条目，不要求命名、分类、评价。
- 扩展只申请本机回环地址的权限。

**待讨论**：

- Agent 经 MCP 收下（[第 15 条](discussion.md#15-agent-能不能直接收下)）：建议直接生效，记进改动记录、能撤销，标明是哪个 Agent 收的（A3 A）。
- 晚点：手机入口、关窗后留不留在菜单栏、监听文件夹里的导入（[C1、C2、C5、C7](open-decisions.md#5-收下与入口)）。

<a id="72-获取插件"></a>
### 7.2 获取插件

**已定**（10-28 三类插件，[ADR-003](decisions/ADR-003-plugins.md#1-插件分三类)；11-01 D-a 到 D-f，[open-decisions §1.1](open-decisions.md#11-十条方向)；11-01 P1、P3，[§1.4](open-decisions.md#14-11-01-第二次回复定下的)）：

- 三类插件都是独立进程，按插件协议对接，不进内核。
- 每个获取插件写明获取层级（七个之一）和登录要求（[插件协议](plugin-protocol.md#24-access-与-login)），是给你挑选用的标签，不是闸门。
- 按你排的顺序试，失败换下一个，不论层级。
- 每个平台一组节奏上限，这个平台的获取插件共用。
- 客户端不预置任何插件来源，你自己添加组织或仓库。添加第三方插件来源时确认一次声明：用途是个人备份、离线阅读、注意力整理，账号和法律后果由你自己担。
- 预装两样，都不含平台知识：通用网页获取（P1）、别的工具导出文件的导入（P3）。

**已定**（11-01，[open-decisions §1.3](open-decisions.md#13-随之改写的文档)；11-04 「然后之前调研的所有的方案都可以作为一种插件去弄」，[open-decisions §1.7](open-decisions.md#17-11-04-回复记下的)）：协议对七个层级都开放，读本机客户端数据的 client-hook 也能写成插件，由你自己装。宿主不代装根证书，也不向别的进程注入。这只定了协议能表达什么，没定你自己的获取插件组织收哪些。各方案能不能接，见 [overview](overview.md#6-插件能接哪些方案)。

**已定**（11-03，[插件协议](plugin-protocol.md#39-从文件导入)）：别的工具导出的文件按 official-export 导入，文件怎么来的写进说明，读本机客户端数据的工具导出的也一样。

**已定**（11-04，[open-decisions §1.8](open-decisions.md#18-grill-回答)）：你自己的获取插件七层都收，含 client-hook（R5 A，[第 9 条](discussion.md#9-自己的获取插件组织收什么)）。client-hook 插件单独放一个组织（暂记 `{fetch-org}-hook`），几份 DMCA 通知最多打掉那一组；添加来源时可以一次加两个。插件校验照 10-28 做 GitHub App，用无服务器中转接 webhook，校验在 GitHub Actions 里跑（O3 A，[第 8 条](discussion.md#8-插件怎么校验)）。

**待讨论**：

- 官方组织出一个和平台无关的「链接清单导入」，读 JSON、CSV（建议）。
- 首批平台（[第 10 条](discussion.md#10-首批平台)）：建议按你最常用的平台，每个先做按链接取单条、列你平台收藏夹的两个插件（P9 B）。
- 默认用不用账号（[第 11 条](discussion.md#11-默认用不用账号)）：建议先试不用账号的；轮到能带账号的，你登录过就带上，每行能关（P4 B + P16 A）。
- 读浏览器的登录状态（[第 12 条](discussion.md#12-能不能读浏览器的登录状态)）：建议只读你选的那个站点的 cookie（P7 A）。
- 占屏幕的插件能不能自己跑（[第 13 条](discussion.md#13-占屏幕的插件能不能自己跑)）：建议电脑上在你没碰键鼠、屏幕没锁时跑，一动就停；手机上只在你点「开始」时跑（P19）。
- 晚点：节奏上限的默认值、七个层级在界面上怎么写（[P6、P14](open-decisions.md#7-获取与插件)）。

<a id="73-导入和跟着收"></a>
### 7.3 导入和跟着收

**已定**（10-21，v0.3；11-01 D-c、D-e，[open-decisions §1.1](open-decisions.md#11-十条方向)；11-03，[插件协议](plugin-protocol.md#38-list-与跟着收)）：

- 批量导入先预览（新的、已有的、能补全的），确认后限速导入，能暂停、续上。
- 跟着收只收新出现的，低频；被限流时只暂停出错的那个插件。
- 你自己在平台上的收藏夹和列表，跟着收到的新条目直接收下，不逐条预览。这一条不变。

**已定**（11-04，「可以只收挑的和命中关注的，这个用户可以自己设置和看看」，[open-decisions §1.8](open-decisions.md#18-grill-回答)）：订阅来的东西（RSS、Horizon 这类简报、别人的公开账号）按订阅各自设置：只收你挑的，或者也收命中你关注的。开之前能先看会命中哪些，进来的条目标明命中了哪一片（推断）。

「命中」两种都能用：按主题上你写的关键词，或按和主题条目的相似度（11-04，[第 2 条](discussion.md#2-地图上一直清楚的是什么)）。

**待讨论**：默认用哪种（建议只收挑的；命中建议默认按关键词，相似度由你打开，因为那是模型在挑）。在哪里挑：建议 feed 在现成阅读器里读、加星算收下，本产品跟着收星标（[第 1 条](discussion.md#1-什么东西进资料库)的 A）。

另外几条建议：

- 少数低频的个人来源（一个博客、一个 Mastodon 或 Bluesky 账号）可以一个一个跟着收（C6 B）。第一次拉只记下已有的，不收；之后新出现的收下。
- Horizon 这类当普通 feed：读它的 Atom 或 Markdown 输出，不包装它的 MCP。它的条目是机器挑的，收下时标明。
- 读 feed 和 Horizon 输出的插件不含平台知识，按 P1、P3 的先例放官方组织，随[第 1 条](discussion.md#1-什么东西进资料库)一起答。
- 不做 OPML 整包订阅，OPML 留给阅读器。对比见 [调研 11](research/11-subscriptions-compat-and-wx-cli.md#3-订阅和资料库的边界)。

**待讨论**（晚点）：跟着收进来的在地图上怎么和亲手收下的分开（[M4](open-decisions.md#6-地图与界面)）。

<a id="74-变成文字"></a>
### 7.4 变成文字

**已定**（10-21，v0.3；默认值 10-23，[product-model](product-model.md#81-设置清单)）：

- 每条都有能搜的文字：文章正文、图里的字（带位置）、口播（带时间点）、关键帧、画面描述、AI 摘要、向量。画面描述和 AI 摘要默认关。
- 原样一直留着；机器写的单独成栏，标明是机器写的。
- 重任务只在接电、空闲时做。
- 每一项写明内容会不会离开这台电脑、发到哪里。

**待讨论**（晚点）：本机转写模型什么时候下载（[T2](open-decisions.md#8-转换与-ai)）。

<a id="组织与找回"></a>
<a id="75-找回"></a>
### 7.5 找回

**已定**（10-21，v0.3）：

- 搜标题、正文、图里的字、口播、字幕、画面描述、摘要、笔记；全文、拼音、二字词、语义相近。
- 按平台、类型、时间、命中在哪一栏筛。结果写命中在哪，例如「口播 01:42」，点开跳到那一处。
- 标签三种分开：平台带的、建议的（点了才算）、你的。
- 去重四层：平台身份、内容指纹、同一内容（跨平台，只提示不合并）、你来定。

<a id="76-地图"></a>
### 7.6 地图

**已定**（10-28，[M7](open-decisions.md#6-地图与界面)、[§1.7](open-decisions.md#17-11-04-回复记下的)；10-21，v0.3；11-04，见[原则 9](#4-原则)）：

- 地图是点阵迷雾。位置稳定：系列按顺序摆，其余按内容相似度摆，不整体重排。
- 雾不存状态，没有总量，不显示还有多少没看。
- 没有角色或动物。
- 一直清楚的是你关注的主题：一组条目，它们所在的那片一直清楚；随时能取消，不随时间变淡，不提醒。主题上可以写关键词。已定（11-04，「主题，然后可以是关键词也可以是相似度」，M1 B，[open-decisions §1.8](open-decisions.md#18-grill-回答)）。

**待讨论**：

- 动作另起一个词（S11）。连带：只记发生过的事，例如打开过、记过一句，不存「已读」一类状态（M6 A）。
- 晚点：最先浮出来的字从哪来、一张还是多张、怎么画，在原型上定（[M2–M4、M7、M8](open-decisions.md#6-地图与界面)）。
- 迷雾地图现在是方向，没有原型，不当已成立的新东西讲（[第 17 条](discussion.md#17-兼容和开创各指什么)）。

<a id="77-你写的那一层"></a>
### 7.7 你写的那一层

**已定**（10-21，v0.3 的原则；规则 10-23，[product-model](product-model.md#6-知识层)）：

| 东西 | 谁写 | 机器能改吗 |
|---|---|---|
| AI 摘要 | 模型，本机或云端，可以关 | 能重算；标明模型和时间 |
| 记一句 | 你；Agent 只能提议 | 不能 |
| 主题页 | 你；模型或 Agent 只能起草 | 不能改你接受过的字 |
| 卡片 | 你 | 不能 |

- 草稿只以改动提议出现，你逐段接受、改了再接受，或者不要。新条目加入主题不改主题页。
- 引用自带原话和位置；被引用的条目删掉以后，这一页照样完整。原文和口播文字里划下的句子能引用进主题页。
- 主题页是普通 Markdown，Obsidian 能打开和编辑；外部改过，本产品重新读。
- 对资料库提问不在本产品里做，用你自己的 Agent。

**已定**（11-04，[第 3 条](discussion.md#3-知识的单位)，[open-decisions §1.8](open-decisions.md#18-grill-回答)）：主题页是单位，它就是你关注的那个主题（[7.6](#76-地图)）；条目是证据，记一句是对一整条的一句，机器只经改动提议起草（T1 A）。卡片保留，可选（[M5](open-decisions.md#6-地图与界面) A）；贴在原文某一处的，走划线（M9 A）。

<a id="agent"></a>
<a id="78-agent"></a>
### 7.8 Agent

**已定**（10-20，[CLAUDE.md](../CLAUDE.md) 原则 5、6；10-21，v0.3；私密 10-23，[product-model](product-model.md#71-条目)）：

- MCP：搜、读、提议改动、应用、撤销；不给删除和外发。工具表见 [SPEC](SPEC.md)。
- ACP（Agent Client Protocol）：本产品当客户端，启动你已经装的 Agent，并把自己的 MCP 交给它。
- 命令行、Agent Skill 文件、本机接口。
- 活动记录：搜了什么、读了什么、提议了什么；每次写入都记下是谁。
- 应用里不自建聊天助手。私密的条目不给 Agent。

**待讨论**：

- 直接收下（[第 15 条](discussion.md#15-agent-能不能直接收下)）：建议直接生效（A3 A），见 [7.1](#71-收下)。
- 晚点：ACP 会话在窗口里显示什么、改动提议多久作废（[A1、A2](open-decisions.md#9-agent)）。

<a id="79-导出与互通"></a>
### 7.9 导出与互通

**已定**（10-20，[CLAUDE.md](../CLAUDE.md) 技术栈；10-28，[ADR-003](decisions/ADR-003-plugins.md#7-导出与读回)）：资料库就是普通文件（Markdown、媒体和 JSON），不开本产品也能读。导出插件写进 Obsidian 等笔记软件，按规则读回你在那边的改动。

**方向已定**（11-04 「然后我希望兼容性和开创性都需要具备」，[open-decisions §1.7](open-decisions.md#17-11-04-回复记下的)）；各指什么，**待讨论**（[第 17 条](discussion.md#17-兼容和开创各指什么)）：建议兼容靠标准，开创只说今天站得住的五件，见 [overview §7](overview.md#7-兼容和开创)；要不要把资料库导出成 feed，也在这一条问。

**待讨论**（晚点）：迁出格式、主题页默认导出到哪（[E1、E2](open-decisions.md#10-导出与互通)）。

<a id="710-存储删除与联网"></a>
### 7.10 存储、删除与联网

**已定**（10-20，[CLAUDE.md](../CLAUDE.md) 原则 3；10-21，v0.3；10-23，[product-model](product-model.md#82-刻意不存在的设置)）：资料库是一个目录，能备份到 WebDAV、S3 或另一个文件夹。删除只由你发起，不自动删很久没看的。

**已定**（11-04，K1 A、K3 A，[第 4 条](discussion.md#4-删掉以后留下什么)）：删掉的先进回收站，默认 30 天。另留一份删除记录，只记身份和标题：跟着收再遇到就跳过，你自己再粘贴时问一句「以前删过」。「彻底忘掉」连记录一起清。

**待讨论**：

- 「只留文字」放在设置的存储页和条目页的「更多」里（K2 B，建议）。
- 同步：方向已定（11-04，[open-decisions §1.8](open-decisions.md#18-grill-回答)）。学 [Hatoba](https://github.com/scarletkc/Hatoba)：跑在你自己的 Cloudflare 账号里，没有本产品的服务器；设备上先端到端加密再上传；增量同步，冲突逐条看；以后再支持 WebDAV 等。媒体放哪、索引按机器分开、要不要也允许同步盘，见[第 14 条](discussion.md#14-资料库能不能放进同步盘)。
- 晚点：默认连哪些网络服务（[K8](open-decisions.md#11-存储同步与联网)）。

<a id="生命周期"></a>
<a id="8-条目的状态"></a>
## 8. 条目的状态

一条有四个互不影响的维度。没有「没整理」「没看」这种维度。

| 维度 | 取值 | 怎么变 | 标 |
|---|---|---|---|
| 存下了多少 | 只有链接、部分、都存好了 | 只升不降 | 已定（10-21，v0.3） |
| 后台任务到哪一步 | 每个任务单独算 | 后台推进，细则见 [product-model](product-model.md#72-处理任务) | 已定（10-21，v0.3） |
| 存在 | 正常、只留文字、在回收站、已清除 | 只由你触发，到期清除除外 | 已定（11-04，[第 4 条](discussion.md#4-删掉以后留下什么)） |
| 私密 | 开、关 | 你 | 已定（10-23，[product-model](product-model.md#71-条目)）：不给 Agent，不进导出 |

界面上不说「完整度」，直接说缺什么，例如「只有链接」「缺视频：平台没提供原文件」。

<a id="6-不做"></a>
<a id="9-不做"></a>
## 9. 不做

**已定**（10-21，v0.3；10-23，[product-model](product-model.md#9-产品边界)；11-01，D-f，[open-decisions §1.3](open-decisions.md#13-随之改写的文档)）：

- 云账号、协作、分享、推荐、社交；通知、提醒、复习、打卡、未读数；应用里自建的聊天助手。
- 内核和官方组织里的平台获取代码；宿主自己代装根证书、向别的进程注入。读本机客户端数据的插件你可以自己装，见 [7.2](#72-获取插件)。
- 通用笔记软件：只有记一句、卡片、主题页三处能写，长篇写作交给 Obsidian 等。
- 替你自动分类或删除；批量收别人的账号做对标分析。
- 拦你刷，替你过滤外面的信息。本产品只管你已经收下的。

刻意不存在的设置：通知开关、每日回顾时间、全部标为已读、连续天数和目标、自动删除很久没看的、自动分类直接生效、允许 Agent 删除。

**待讨论**（[第 12 条](discussion.md#12-能不能读浏览器的登录状态)）：读你自己浏览器里某个站点的 cookie 算不算在不做里。建议不算；宿主不做的是解密平台客户端的数据、装证书做中间人（P7 A）。

<a id="7-成功标准"></a>
<a id="10-成功标准"></a>
## 10. 成功标准

**已定**（10-21，v0.3）：

- 找回率：搜索后 60 秒内打开某一条的比例。
- 保存摩擦：从按下到「收下了」的时间；要多输入一步的占比，目标是 0。
- 保险赔付率：原帖已经没了、本机还能读的条目占比，按平台分。
- 回访价值：收下 7 天后被打开过的比例。
- 不追求：日活、收下的总数、使用时长。

**待讨论**（晚点）：这些在哪算、给谁看（[S13](open-decisions.md#3-叙事与介绍)）。

<a id="9-风险"></a>
<a id="11-风险"></a>
## 11. 风险

| 风险 | 怎么应对 | 标 |
|---|---|---|
| 平台改版，插件失效 | 插件外置，按你排的顺序换下一个；原样留着 | 已定（11-01，[D-c](open-decisions.md#11-十条方向)） |
| 维护者收到律师函 | 函件发给维护者（[调研 06](research/06-platform-access-and-account-risk.md#163-下架停更与法律风险)）。例如 jackwener/wx-cli 因腾讯方面的 DMCA 通知，2026-07-15 起被 GitHub 屏蔽（[通知](https://github.com/github/dmca/blob/master/2026/07/2026-07-13-wechat.md)，2026-07-13；[调研 11](research/11-subscriptions-compat-and-wx-cli.md#1-wx-cli)）。应对：内核和官方组织里没有平台获取逻辑；七层都收（11-04），一个插件一个仓库，一次通知只波及那个仓库和它的 fork；client-hook 单独一个组织，GitHub 按 [DMCA 政策 F 节](https://github.com/github/site-policy/blob/main/Policies/content-removal-policies/dmca-takedown-policy.md)停用多次侵权的账号时，主组织不受牵连 | 已定（11-04，[第 9 条](discussion.md#9-自己的获取插件组织收什么)） |
| 平台账号受限 | 后果由你担，添加插件来源时确认一次声明；节奏上限 | 已定（11-01，见 [7.2](#72-获取插件)） |
| 本机算力不够 | 识别能选本机或云端，第一次打开时说清 | 已定（10-21，v0.3） |
| 地图变成一团乱麻 | 位置稳定、语义缩放、不整体重排 | 已定（10-21，v0.3） |
| feed 把地图淹掉 | 只让你拿的进来 | 待讨论：[第 1 条](discussion.md#1-什么东西进资料库) |
| 名字撞名 | 候选是 Dokokara（暂名，你倾向）和 Yohaku（[调研 09 §12](research/09-fog-and-name.md#12-11-03dokokara-与-yohaku) 比过）；选 Yohaku 要接受和 Innei 的「余白 / Yohaku」、Mac 上的「YOHAKU – liquid notes」同名 | 待讨论：[第 5 条](discussion.md#5-名字) |

## 12. 开发顺序

- **已定**（10-21，[O8](open-decisions.md#13-开源与发布)）：不分 M0–M3 那样的里程碑。顺序是产品逻辑 → 界面设计 → 实现。
- **已定**（11-04，「然后开发先开发主要功能，然后后续按照prd慢慢优化其他的就行，因为主要的东西可能会根据我的实际体验去变和优化这样」，[open-decisions §1.8](open-decisions.md#18-grill-回答)）：先做主要功能，用起来以后按本 PRD 一项项补；主要功能本身也会按你的实际体验改。主要功能包括哪些，另问。
- **已定**（10-20，[CLAUDE.md](../CLAUDE.md) 开发流程）：每个功能先写 feature doc，你确认后才写代码。
- **待讨论**：第一段代码从哪开始，等你看完四份入口文档再问，见 [TODO §4](TODO.md#4-开始写代码)。写代码前要先答[第 14 条](discussion.md#14-资料库能不能放进同步盘)；接口先写第 0、1 层（[overview](overview.md#5-接口做到哪了)）。步骤见 [TODO](TODO.md#3-原型和量测)。
