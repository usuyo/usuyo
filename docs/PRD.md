# 歇存 Xiecun — PRD v0.3

状态：草案 · 2026-10-21 · 取代 v0.2

## 1. 定位

歇存是一款开源的注意力回收工具。

各平台的收藏夹是平台的留存手段，不是你的资产：你收藏得越多，欠平台的注意力越多，而且内容随时会被删除、下架、锁进登录墙。歇存把这些内容收回到你自己的本地资料库，变成文本（文章正文、图片里的文字、视频的口播和关键帧），让你能搜索、能整理、能交给自己的 AI Agent 处理，最后把真正要看的东西变少。

口号方向：平台要你一直刷，歇存让你歇一下。

## 2. 用户

首版用户就是作者本人这一类人：用 Claude Code / Codex 等 Coding Agent 做知识工作的中文个人用户，内容来源横跨抖音、小红书、B站、公众号、视频号、X。不为大众收藏用户设计。

## 3. 核心链路

遇见 → 收下 → 变成文本 → 找回 → 提炼 → 放下

- 收下：任何入口，一瞬间落成条目，不要求命名、分类、评价。
- 变成文本：无论文章、图片、视频，最终都有一份可搜索的文本，并保留原始数据和图片。
- 找回：全量搜索，覆盖标题、正文、图中文字、口播、字幕、画面描述、摘要、笔记；可按来源/类型/时间/命中层筛选。
- 提炼：画布上把很多素材收拢成少数线索和念头；Agent 可以协助，但只提议。
- 放下：由用户主动发起的瘦身与删除，不提醒不催促。

## 4. 原则

1. 内核平台中立，来源全是社区适配器（Tachiyomi/Mihon 模式）。
2. raw 永远保留；平台原文、机器识别、AI 产物、用户笔记四层分开存放和展示。
3. 本地文件是真相源，索引可重建；存储位置可选（本地目录、WebDAV、S3、自有云盘）。
4. 一切可插拔：获取方式、识别器、模型、Agent、存储。本地还是云端由用户选，只保证透明（标明数据是否离开本机）。
5. 不制造压力：没有未读数、待办队列、打卡、连续奖励；没有"未整理"状态。
6. AI 原生：MCP 对外、ACP 接入用户已有的 Agent、CLI、本地 HTTP API；应用内不自建聊天助手。
7. 全开源：内核 AGPL-3.0，适配器协议与 SDK MIT。不商业化。

## 5. 功能范围

### 收集入口
- 粘贴/拖入链接或文本；文件/截图导入
- 浏览器扩展：保存当前页（所见即所存）
- 全局快捷键
- 手机 → 桌面投递（局域网直传；自有云盘监听目录；文件传输助手兜底）
- MCP / CLI / HTTP API

### 导入方式
- 单条：有接口直接调接口
- 批量：收藏夹列表、官方数据导出包、链接列表、文件夹、其他工具导出；先扫描预览（新增 / 已有 / 可升级完整度），确认后限速导入，可暂停续传
- 同步：订阅收藏夹/账号/公众号/RSS，增量、低频、单会话，遇风控自动退避并告知

### 处理
- 规范化：raw → 文本 + 图片
- 识别：OCR（带坐标）、ASR（带时间戳）、关键帧、画面描述（可选）、向量化
- 只在空闲且接电时运行重任务

### 组织与找回
- 三种标签来源分开：平台原带 / 引擎建议 / 用户确认
- 四层去重：身份（平台 ID）→ 内容指纹（文本 SimHash、图片/关键帧感知哈希）→ 同源组（跨平台同一内容，不自动合并）→ 用户裁决
- 全量搜索 + 筛选 + 拼音 + 二字词 + 语义相近
- 画布：节点（素材 / 线索 / 念头）、连线（出处 / 相关 / 同源）、可重叠分组、语义缩放、注意力状态（未注意 / 注意到 / 已消化 / 放下）。不是思维导图：一条素材可属于多个分组，没有唯一中心。

### Agent
- MCP：search / get（可选层）/ propose_changes / apply / undo；不提供删除、外发
- ACP：歇存作为客户端启动用户已装的 Agent，并在 session/new 注入自己的 MCP
- 活动记录：搜了什么、读了什么、提议了什么；可整批撤销

### 生命周期
收下 → 认身份 → 获取 → 规范化 → 识别 → 整理（可选）→ 维护（换源重取、刷新、重算、存活检查）→ 放下（瘦身 → 回收站 30 天 → 清除）

三个独立的状态维度：完整度（仅链接 / 部分 / 完整，只升不降）、处理任务进度、存在状态（正常 / 已瘦身 / 回收站）。

## 6. 不做

- 云账号、协作、内容推荐
- 内置任何平台的抓取代码；内置需要本地代理/解密的工具
- 自动分类替用户做决定
- 批量抓取他人账号的"对标分析"（以后若做，作为独立插件包）
- 通知、打卡、未读数

## 7. 成功标准

- 找回率：搜索后 60 秒内打开某条内容的比例
- 保存摩擦：按下到"收好了"的耗时；需要额外输入的保存占比（目标 0）
- 保险赔付率：原帖已失效但本地仍可读的条目占比，按平台分
- 回访价值：收下 7 天后被打开过的比例
- 明确不追求：日活、收藏总数、使用时长

## 8. 里程碑

- M0 契约与内核：内容包、生命周期、去重、CLI、MCP。无 GUI。
- M1 通用能力与适配器协议：粘贴/扩展/手机桥、通用正文抽取、OCR、ASR、关键帧；参考适配器 2 个（公众号最简、抖音最难）
- M2 批量与同步：收藏列表适配器（参考 opencli）、ACP 接入
- M3 画布与社区：画布视图、适配器源机制、签名与健康上报

## 9. 风险

- 平台接口随时失效 → 适配器外置、换源重取、raw 保留
- 法律与平台规则 → 内核中立、只做个人使用、不绕技术措施、核心团队不维护平台适配器
- 本机算力 → 识别可选本地或云端，启动时告知本机能跑什么
- 画布变成另一个毛线团 → 位置稳定、语义缩放、不整体重排
