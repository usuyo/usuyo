# PRD

产品为什么做、做什么、不做什么。字段、目录、命令和错误码在 [SPEC](spec/README.md) 和[插件协议](protocol/README.md)；做到哪、接着做什么在[总纲](BUILD.md)。产品名 usuyo，只用拉丁字母，小写；正文有时写「本产品」。

<a id="1-定位"></a>
<a id="1-为什么做"></a>
## 1. 为什么做

- 平台的收藏夹是平台留住你的办法，不是你的东西。帖子会删、会下架、会锁进登录墙。
- 想回头看一条，得回到推荐流里。推荐流、「建议收藏」式的标题、一键 AI 总结，都在替你挑看什么，AI 总结里也混着大量垃圾。
- 收了一大堆以后，不知道从哪下手。你说：「那个雾感觉有点脑雾的那种，因为就是你收藏了一大堆，但是却不知道从何开始去处理」。

本产品把你收下的东西原样存到你自己的电脑上，转成能搜的文字，让你自己的判断留在最上面一层。

它像个人知识库，但单位是思路：从你散在各处的收藏里拼出来的一条线。收下的东西是你的论据和素材，文字要能被提取，图和视频本身也是素材；你在上面加自己的理解、理出整条思路，再写出自己的东西。创作之前的这些事，本产品全包。

产品不驱散雾，只给一个进去的口子，从哪一片进都行，其余的留在雾里也没关系；不承诺清掉什么。

<a id="2-给谁"></a>
## 2. 给谁

作者本人这一类：用 Claude Code、Codex 这类 Coding Agent 做知识工作的中文个人用户。收下的东西散在抖音、小红书、B站、公众号、视频号、X 等平台。不为大众设计。

<a id="3-是什么和不是什么"></a>
## 3. 是什么和不是什么

一句话：

> 开源的本地优先桌面应用：把在各平台收藏的内容备份到本机，转成可搜索的文字。

被问「这是什么」时接一句：

> 添加获取插件后，你在各平台收下的内容存到自己电脑上，口播和图里的字能搜，回头看不用再进推荐流。

和相近的东西比（[调研 07](research/07-positioning-and-naming.md#11-和相近东西的区别)）：

| 相近的 | 区别 |
|---|---|
| 个人知识库 | 它的单位是你整理过的笔记，没整理的就是欠着的活。本产品的单位是你收下的原样，你的判断另成一层；只收下、不整理也正常。知识库管你知道什么，本产品管你看重什么。你说过：「可以说个人知识库但是实际上也不是」 |
| 稍后读 | 它是待读队列，收下就答应以后要读。本产品没有队列，收下不带这个承诺 |
| 书签、平台收藏夹 | 存的是链接，帖子一删就失效；平台收藏夹还是推荐信号。本产品存内容的副本和转出的文字 |
| AI 总结 | 总结是模型替你挑，还常顶替原文。本产品转写是为了能搜；AI 摘要默认关，开了也单独一栏，原样一直在。杂讯指的是顶替原文的总结；这里原样、转出的文字、每一步分析都留着，指得回去、能重做，所以可以让模型从不同角度分析、分出不同的支线，分析另成一层，不顶替原样 |

<a id="4-原则"></a>
## 4. 原则

1. **内核和官方组织里没有平台获取逻辑。** 自己维护的获取插件放在 `usuyo-fetch`。随安装包预装的只有通用网页获取和别的工具导出文件的导入，都不含平台知识。
2. **机器永不改写或删除原样。** 取回来的原样只增不改；转写、识别、AI 产物另放，可以重算。只在你选「只留文字」或「删掉」时移走，先进回收站。
3. **文件是真相，索引可丢、可重建。** 同步跑在你自己的 Cloudflare 账号里，离开本机前加密，本机的资料库照旧是明文文件（[7.10](#710-存储删除与联网)）。
4. **不制造压力。** 没有未读数、待办队列、打卡；整理是可选的，没有「没整理」这种状态；不说清空、进度、处理完。文案细则见 [5.1](#51-文案)。
5. **入库内容和插件输出都是不可信输入。** 给 Agent 的内容标明不可信和出处；写操作只收结构化参数；MCP 不给删除和外发，Agent 撤掉它自己收进来、你没写过东西的条目不算删除。
6. **Agent 和模型改已有内容先提议，你确认后生效，可以整批撤销；收下新条目直接生效，记进改动记录，标明是哪个 Agent 收的，也能整批撤销。**
7. **能换的都能换。** 获取、转换、导出三类插件（[ADR-003](decisions/ADR-003-plugins.md#1-插件分三类)），还有模型、Agent、存储位置。本机还是云端由你选，离开本机的都标明去向。
8. **只做开源，不商业化，没有云账号。** 开发期仓库私有，公开前再定哪些文档公开。内核 AGPL-3.0；插件协议的 schema 和 plugin-kit 用 MIT。
9. **视觉来自软件本身。** 雾是点阵（圆点或方像素）；文字、连线、卡片、控件用现代界面和真正的排版；不做终端风格的字符界面；变化都和雾走同一个时钟；没有角色或动物，图标、README 头图、空资料库那一屏只用点阵雾和名字本身。

兼容和开创没有单独成一条原则，落在 [7.9](#79-导出与互通) 和 [7.7](#77-你写的那一层)。

<a id="5-用到的词"></a>
## 5. 用到的词

产品里说「收下、存着、回头看」。「来源」不再单独用，拆成插件来源、列表、出处、引用。「同步」指设备之间的同步。

| 词 | 标识 | 意思 |
|---|---|---|
| 收下 | `add` | 一条内容进资料库，不论哪个入口；之后就是存着，不计数 |
| 回头看 | — | 你搜到、打开、在地图上撞见一条 |
| 资料库 | `library` | 一个目录，文件都在里面 |
| 条目 | `item` | 收下的一条内容，连同它的文件 |
| 原样 | `raw` | 取回来的那一份，机器不改 |
| 快照 | `snapshot` | 某一次取回来的原样，只增不改 |
| 只留文字 | `keep-text` | 删掉视频和原图，留下文字和缩略图 |
| 回收站 | `trash` | 删掉的先放这里，到期清干净 |
| 同一内容 | `sameAs` | 不同平台上的同一份内容，只提示，不合并 |
| 导入 | `import` | 一次从平台的收藏夹或别的工具导出的文件收下一批 |
| 栏 | — | 同一条的不同文字：原文、图里的字、口播、画面、AI 摘要、你的笔记 |
| 地图 | `map` | 按顺序和相似度摆开条目，位置稳定 |
| 雾 | `fog` | 没打开、没选中部分的画法；不存状态，没有总量 |
| 口子 | `opening` | 你指向、搜到或打开时雾张开的一小块 |
| 关注 | — | 让一个主题所在的那片地图一直清楚，不随时间变淡；取消叫「不再关注」 |
| 主题页、记一句 | `topic`、`takeaway` | 你起名的一组条目和它的 Markdown 页；你对一整条写的一句 |
| 卡片 | `card` | 你的一个观点，一段话，能引用条目 |
| 成稿 | `draft` | 你想表达的成品：文章、帖子、脚本，由卡片和主题页攒成，每句带引用 |
| 获取层级 | `access`、`login` | 插件靠哪一层拿内容、要不要登录；七层见[插件协议](protocol/manifest.md#24-access-与-login) |
| 获取插件组织 | `usuyo-fetch`、`usuyo-fetch-hook` | 你自己的获取插件组织；client-hook 插件单独放后一个 |
| 插件来源 | `pluginSource` | 你添加的组织名或 `owner/repo` |
| 列表 | `source` | 插件能列出的一个收藏夹或清单 |
| 出处 | `origin` | 一条从哪个平台、链接、入口进来 |
| 引用 | `citation` | 主题页里指回条目的一处，带原话和位置 |
| 跟着收 | `subscription` | 跟着一个列表，定期收下新出现的 |
| 改动提议、改动记录 | `changeset`、`journal` | 确认才生效，可整批撤销 |

<a id="51-文案"></a>
### 5.1 文案

1. 按钮写「动词 + 对象」，有后果就写后果：「删掉这条（30 天内能恢复）」。不写「放下」「处理」「确定」。
2. 状态写事实，不写评价：「视频没存下来：平台没提供原文件」，不写「部分完整」。
3. 数字只描述这一次操作的结果：「删掉 23 个视频，腾出 4.1 GB」可以。描述积压的数字不出现：没有「还有 128 条」。
4. 「收藏」只用来指平台上的收藏夹，比如「抖音收藏夹」，不指 usuyo 里的动作。
5. 下表左列的词不出现在界面上：

| 不说 | 改说 |
|---|---|
| 收藏（指 usuyo 的动作时） | 收下、存着 |
| 待办、待整理、未读、已消化 | 不出现 |
| 完整度、部分完整 | 说缺什么 |
| 适配器、获取方式 | 获取插件 |
| 变更集 | 改动提议 |
| 提炼 | 起草、汇总成一页 |
| 瘦身 | 只留文字 |
| 放下 | 具体动作名：只留文字、删掉 |

6. 多语言：消息 id 用英文点分，例如 `item.keepText.confirm`；简体中文是源语言，English 必须带同样的后果信息；不拼接句子；数字、日期、文件大小用 `Intl` 格式化。

<a id="6-主循环和一个例子"></a>
## 6. 主循环和一个例子

收下 → 变成文字 → 回头看（搜到、打开）→ 你写的那一层（记一句、主题页、卡片、成稿、关注一个主题）

- 每一步都可以停，只收下、从不整理是正常用法（[原则 4](#4-原则)）。
- 存进来的就留着，不做催你清掉一批的功能；只留文字和删掉只由你一条条或一批批发起。

例子：周三晚上在抖音刷到一条 4 分钟的手冲咖啡教学。你之前添加过抖音的获取插件。

| 阶段 | 你做了什么 | 看到什么 |
|---|---|---|
| 收下 | 复制分享链接，按全局快捷键，粘贴，回车 | 浮层写「收下了」，一秒后消失 |
| 获取 | 不用做什么 | 这条从「只有链接」变成封面和标题 |
| 变成文字 | 不用做什么；默认等接上电源、电脑空闲时做 | 条目页多出「口播文字」「画面」两栏 |
| 找回 | 两个月后搜「水温 92」 | 结果写「口播 01:42」，点开从那一秒播 |
| 记一句 | 看完点「记一句」，写「92 度，闷蒸 30 秒」 | 条目上出现这句话 |
| 汇总 | 搜「手冲」，全选 23 条，放进新主题，点「起草这一页」 | 草稿每段标着出自哪几条，你逐段接受 |

结果：23 条都还在，多了一页你的话；要回到原话，引用里就有。

<a id="5-功能范围"></a>
<a id="7-功能"></a>
## 7. 功能

<a id="收集入口"></a>
<a id="71-收下"></a>
### 7.1 收下

- 入口：粘贴、拖入、全局快捷键、浏览器扩展「保存当前页」、命令行、本机接口、投递（扩展、油猴脚本、手机快捷指令，[插件协议](protocol/delivery.md#5-投递接口)）、监听文件夹，Agent 经 MCP。
- 一瞬间落成条目，不要求命名、分类、评价。
- Agent 收下直接生效，记进改动记录、能撤销，标明是哪个 Agent 收的。
- 扩展只申请本机回环地址的权限。

点扩展时才判断当前标签页能由哪个获取插件收下，并写出来；不在你浏览的每一页上被动提示。

<a id="72-获取插件"></a>
### 7.2 获取插件

- 三类插件都是独立进程，按插件协议对接，不进内核（[ADR-003](decisions/ADR-003-plugins.md#1-插件分三类)）。
- 每个获取插件写明获取层级（七个之一）和登录要求（[插件协议](protocol/manifest.md#24-access-与-login)），是给你挑选用的标签，不是闸门。
- 按你排的顺序试，失败换下一个，不论层级。
- 每个平台一组节奏上限，这个平台的获取插件共用。
- 客户端不预置任何插件来源，你自己添加组织或仓库。添加第三方插件来源时确认一次声明：用途是个人备份、离线阅读、注意力整理，账号和法律后果由你自己担。
- 预装两样，都不含平台知识：通用网页获取、别的工具导出文件的导入。别的工具导出的文件按 official-export 导入，文件怎么来的写进说明，读本机客户端数据的工具导出的也一样（[插件协议](protocol/fetch.md#39-从文件导入)）。
- 协议对七个层级都开放，读本机客户端数据的 client-hook 也能写成插件，由你自己装。宿主不代装根证书，也不向别的进程注入。你自己的获取插件组织七层都收；client-hook 插件单独放 `usuyo-fetch-hook`，几份 DMCA 通知最多打掉那一组；添加来源时可以一次加两个。
- 插件校验用 GitHub App：无服务器中转接 webhook，校验在 GitHub Actions 里跑。
- 平台都要：小红书、微信视频号、B 站、X 在前，其余（抖音、快手、微博、贴吧、知乎、YouTube）接着做。每个平台有「按链接取一条」和「列你的收藏」，还能按关键词搜、按创作者主页列；搜和列出来的不自动进库，你挑了才收下。评论可选：默认不取，按平台或按条打开，取多少能自定义。MediaCrawler 是非商业学习许可，代码不能用，只参照做法。电脑版微信收藏和合并转发不做。
- 要账号的和不要账号的分开：不要账号能拿到的（多半是单条的文字、图、视频）一律不带账号去取，登录了也不带；账号只用在非它不可的那几样上（多半是列出你存过的），插件清单里写明是哪几样。
- 登录两种，每个平台可选：内置浏览器里扫码（默认），或用你日常浏览器里已登录的状态，只读你选的那个站点的 cookie、只在内存里用。第一次用到时问一次，日常浏览器里登录过就预选它。
- 占屏幕的插件什么时候跑，每个插件单独设置：随时、你没在用时（一动键鼠就停）、只在你点开始时。默认按插件声明的会不会动键鼠和剪贴板来定；动过剪贴板的，跑完放回去。

各方案能不能接（层级见[插件协议](protocol/manifest.md#24-access-与-login)）：

| 方案 | 层级 | 能吗 | 缺什么 |
|---|---|---|---|
| 平台获取 | public-web 到 private-api | 能，没逐项核 | — |
| 电脑、手机的视觉层 Agent | vision-ui | 能 | — |
| 包装你自装的 wx-cli 一类工具 | client-hook | 部分 | 私有 `HOME`；连本机 socket 的权限 |
| 插件自己取密钥 | client-hook | 不能 | 宿主不给调试器和 sudo；密钥你先用那个工具取好，插件只包装 |
| 导入这类工具导出的文件 | official-export | 能 | 无，照[协议](protocol/fetch.md#39-从文件导入) |
| RSS、Atom、JSON Feed 跟着收 | public-web | 部分 | 你填的地址、第一次拉、条目身份 |
| 跟着收阅读器的星标 | — | 部分 | `sites` 填不了你自己的阅读器 |
| 读 Horizon 的 Atom 或 Markdown | public-web 或导入 | 能 | 没字段标原文是机器写的 |
| 上游的打分和摘要 | — | 不能 | 获取插件写不了 `derived/` |
| OPML 导入订阅 | — | 不能 | 订阅没有文件格式 |
| 跨条目简报 | — | 不能 | 没有这类插件 |

条目详情里一行写这条是怎么取回的：哪个获取插件和来源、用没用账号、时间、插件版本；平台指标拿不到写「没拿到」，不写 0。不经 ADB 驱动安卓手机取内容，也不做安卓配套 App；只在手机上有的列表，用别的工具导出成文件再导入。

<a id="导入方式"></a>
<a id="73-导入和跟着收"></a>
### 7.3 导入和跟着收

- 批量导入先预览（新的、已有的、能补全的），确认后限速导入，能暂停、续上。
- 跟着收只收新出现的，低频；被限流时只暂停出错的那个插件（[插件协议](protocol/fetch.md#38-list-与跟着收)）。
- 你自己在平台上的收藏夹和列表，跟着收到的新条目直接收下，不逐条预览。
- 订阅来的东西（RSS、Horizon 这类简报、别人的公开账号）按订阅各自设置：只收你挑的，或者也收命中你关注的。开之前能先看会命中哪些，进来的条目标明命中了哪一片。
- 「命中」两种都能用：按主题上你写的关键词（默认），或按和主题条目的相似度（你打开）。两种都看标题层和内容层（口播转的文字、字幕、正文、图里的字），画面层默认不算，因为口播的画面常和内容无关。
- 少数低频的个人来源（一个博客、一个 Mastodon 或 Bluesky 账号）可以一个一个跟着收。第一次拉只记下已有的，不收；之后新出现的收下。
- Horizon 这类当普通 feed：读它的 Atom 或 Markdown 输出，不包装它的 MCP。它的条目是机器挑的，收下时标明。读 feed 的插件不含平台知识，放官方组织。
- 不做 OPML 整包订阅，OPML 留给阅读器（[调研 11](research/11-subscriptions-compat-and-wx-cli.md#3-订阅和资料库的边界)）。

<a id="74-变成文字"></a>
### 7.4 变成文字

- 每条都有能搜的文字：文章正文、图里的字（带位置）、口播（带时间点）、关键帧、画面描述、AI 摘要、向量。画面描述和 AI 摘要默认关。
- 说的话、画面里的字、画面本身、配的文字，每一面都认出来、摆出来；机器不筛、不删哪一面，哪一面要紧由你判断，只有特别明显的（比如画面一直是同一张图）机器标出来。
- 原样一直留着；机器写的单独成栏，标明是机器写的，能换个工具重做。
- 重任务只在接电、空闲时做。
- 每一项写明内容会不会离开这台电脑、发到哪里。

<a id="组织与找回"></a>
<a id="75-找回"></a>
### 7.5 找回

- 搜标题、正文、图里的字、口播、字幕、画面描述、摘要、笔记；全文、拼音、二字词、语义相近。
- 按平台、类型、时间、命中在哪一栏筛。结果写命中在哪，例如「口播 01:42」，点开跳到那一处。
- 标签三种分开：平台带的、建议的（点了才算）、你的。
- 去重四层：平台身份、内容指纹、同一内容（跨平台，只提示不合并）、你来定。

<a id="76-地图"></a>
### 7.6 地图

- 地图是点阵迷雾。位置稳定：系列按顺序摆，其余按内容相似度摆，不整体重排。
- 雾不存状态，没有总量，不显示还有多少没看；不记你在哪停留过，没有「雾 N%」这类读数，新收下的条目不闪。只记发生过的事，例如打开过、记过一句，不存「已读」一类状态。
- 一直清楚的是你关注的主题：一组条目，它们所在的那片一直清楚；随时能取消，不随时间变淡，不提醒。动作叫「关注」，取消叫「不再关注」；界面上写明关注的是主题，不是人。主题上可以写关键词。
- 打开就是迷雾地图，搜索框浮在地图上面，不做信息流。
- 地图上不弹卡片：条目细节、搜索结果放在旁边。
- 首页能选地图按什么排：按主题，也能按来源；形态可以有多种，换排法时内容跟着变换，有动效。要的是整套界面，地图和你的各种操作一起设计，不是只有一张地图。

<a id="77-你写的那一层"></a>
### 7.7 你写的那一层

| 东西 | 谁写 | 机器能改吗 |
|---|---|---|
| AI 摘要 | 模型，本机或云端，可以关 | 能重算；标明模型和时间 |
| 记一句 | 你；Agent 只能提议 | 不能 |
| 主题页 | 你；模型或 Agent 只能起草 | 不能改你接受过的字 |
| 卡片 | 你；模型或 Agent 只能起草 | 不能改你接受过的字 |
| 成稿 | 你；模型或 Agent 只能起草 | 不能改你接受过的字 |

- 主题页是单位，它就是你关注的那个主题（[7.6](#76-地图)）；条目是证据。记一句是对一整条的一句；贴在原文某一处的，走划线。卡片可选。
- 从素材到你想表达的是一条链路：素材（条目的文字层，划线、记一句）→ 卡片（你的一个观点，引用几条素材）→ 主题页（整理、总结一个主题）→ 成稿（文章、帖子、脚本等你想表达的）。每一句都能点回原文那一段、那一秒。每一步你自己写，或让模型、你的 Agent（经 MCP）起草。
- 草稿只以改动提议出现，你逐段接受、改了再接受，或者不要。新条目加入主题不改主题页；主题页上有「用某天之后加入的条目起草补充」，日期由你选。
- 引用自带原话和位置；被引用的条目删掉以后，这一页照样完整。原文和口播文字里划下的句子能引用进主题页。
- 主题页、卡片、成稿是普通文件，不开本产品也能读。资料库不当 Obsidian vault 用：在 Obsidian 里改的是导出的那份，读回到本产品；划线、标题和自动生成的各层不读回（[7.9](#79-导出与互通)）。
- 对资料库提问不在本产品里做，用你自己的 Agent。

<a id="agent"></a>
<a id="78-agent"></a>
### 7.8 Agent

- MCP：搜、读、收下、提议改动、应用、撤销；不给删除和外发。
- ACP（Agent Client Protocol）：本产品当客户端，启动你已经装的 Agent，并把自己的 MCP 交给它。
- 本机接口、Agent Skill 文件；现有的几条命令行留着。
- 活动记录：搜了什么、读了什么、提议了什么；每次写入都记下是谁。
- 改动提议不作废，也不计数、不提醒。
- 应用里不自建聊天助手。私密的条目不给 Agent。

<a id="79-导出与互通"></a>
### 7.9 导出与互通

资料库就是普通文件（Markdown、媒体和 JSON），不开本产品也能读。资料库的形状按本产品自己的需要定，不迁就笔记软件，它们要的样子由导出转换（[ADR-003](decisions/ADR-003-plugins.md#7-导出与读回)）。导出插件写进 Obsidian 等笔记软件，只导出副本再读回：读回你在那边改的笔记、记一句、标签、主题，以及主题页、卡片、成稿的正文。导出只在你点「现在导出」时跑，读回跟着一起。资料库不往外生成 feed。

兼容靠标准，不靠自己做阅读器（[调研 11](research/11-subscriptions-compat-and-wx-cli.md#4-兼容矩阵)）；开创只说今天站得住的几件；从素材到成稿的链路见 [7.7](#77-你写的那一层)。

| 方向 | 标准或格式 | 怎么做 |
|---|---|---|
| 进 | 链接、扩展投递；书签 HTML，Pocket、Readwise 等导出 | 收下和导入 |
| 进 | RSS 2.0、Atom、JSON Feed 1.1 | 跟着收（[7.3](#73-导入和跟着收)） |
| 进 | Horizon 的 Atom、Markdown 输出 | 当普通 feed，条目标成机器挑的 |
| 进 | Google Reader API | 跟着收阅读器的星标时可能要，没定（[7.3](#73-导入和跟着收)） |
| 进 | OPML 2.0 | 不做整包订阅，留给阅读器 |
| Agent | MCP；包装别的命令行、HTTP、MCP 工具 | MCP 服务；包装走插件 |
| 存 | Markdown 加 front matter、JSON、WebVTT | 资料库的文件 |
| 出 | Obsidian vault 导出并读回；书签 HTML、CSV | 导出插件 |

开创：

- **站得住**：Agent 改动先提议，可整批撤销；raw 和 derived 分开，索引能重建；导出的文件能读回；清单里写明七个获取层级；Keiyoushi 式仓库拆分（客户端不预置插件来源，获取插件另放一个组织）。
- **还没撑住**：迷雾地图、注意力模型。是方向，要原型。

<a id="710-存储删除与联网"></a>
### 7.10 存储、删除与联网

- 资料库是一个目录，能备份到 WebDAV、S3 或另一个文件夹。删除只由你发起，不自动删很久没看的。
- 删掉的先进回收站，默认 30 天，到期就彻底没了，不留记录。你或 Agent 再收下同一条：还在回收站里的直接拿回来，不提醒；不在的就是普通收下。跟着收每个订阅自己记列过哪些，它列过、你删掉的不会被它带回来。回收站里能「立即清除」，不等到期。到期和立即清除都清干净：改动记录里也不留它，你页面里引它的原话和标题照留，链接换成「已删掉」（[SPEC §1.7](spec/library.md#17-删掉)）。
- 删掉主题页，主题页进回收站，条目不受影响。
- 「只留文字」放在设置的存储页和条目页的「更多」里。口播还没转成文字时按钮不能点，写明原因并给「先转文字」。
- 同步学 [Hatoba](https://github.com/scarletkc/Hatoba)：跑在你自己的 Cloudflare 账号里（Worker 加 D1），没有本产品的服务器；设备上先端到端加密再上传；增量同步，冲突逐条看。同步文字和机器转出的文字；媒体（R2，默认上传当备份）、WebDAV 等别的后端等文字同步做完再加（[调研 14](research/14-sync-like-hatoba.md#0-结论)）。资料库也能放 iCloud、Dropbox，但和内置同步二选一；R2 加 30 天桶锁；私密条目也加密上云，可选不上；主密码和恢复码都丢了，还有一台在就清空云端重传。

除了你打开的同步、云端识别和模型下载，默认只连 GitHub：查插件更新、读屏蔽清单、查应用新版本。设置的隐私页列出每一项连到哪里、多久一次，每项都能关；离线时一切照常。

<a id="生命周期"></a>
<a id="8-条目的状态"></a>
## 8. 条目的状态

一条有四个互不影响的维度。没有「没整理」「没看」这种维度。

| 维度 | 取值 | 怎么变 |
|---|---|---|
| 存下了多少 | 只有链接、部分、都存好了 | 只升不降 |
| 后台任务到哪一步 | 每个任务单独算 | 后台推进，见 [8.1](#81-后台任务) |
| 存在 | 正常、只留文字、在回收站、已清除 | 只由你触发；Agent 或接口收下时从回收站拿回来、Agent 撤它自己收进来的放回回收站也算；到期清除除外 |
| 私密 | 开、关 | 你；私密的不给 Agent，不进导出 |

界面上不说「完整度」，直接说缺什么，例如「只有链接」「缺视频：平台没提供原文件」。

<a id="81-后台任务"></a>
### 8.1 后台任务

任务种类：获取、规范化、图里的字、口播文字、关键帧、画面描述、AI 摘要、向量。

| 状态 | 进入 | 离开 | 界面怎么说 |
|---|---|---|---|
| 排队 | 收下或设置打开 | 轮到它 | 不显示 |
| 等条件 | 设置要求接电且空闲 | 条件满足 | 「等接上电源再做」 |
| 在做 | 开始执行 | 完成或失败 | 「正在把口播转成文字」 |
| 好了 | 成功 | 用户点「重做」 | 不显示 |
| 失败 | 出错；自动重试，间隔加倍，最多 3 次 | 用户点「重试」 | 写具体原因：「视频文件损坏，无法读取音轨」 |
| 关了 | 设置里关掉 | 设置打开 | 「口播转文字已关闭（设置 › 变成文字）」 |

设置从关改成开时只对新收下的生效；对已有的提供「对已有的也做一遍」。

<a id="82-其他对象"></a>
### 8.2 其他对象

| 对象 | 状态与转换 | 结束时留下什么 |
|---|---|---|
| 快照 | 获取中 → 存好 / 失败；只增不改；「只留文字」时其中的媒体文件移走 | 原始页面数据 |
| 标签 | 平台带的不可改；建议的点了才变成我的，忽略过的不再建议；我的可加、删、改名、合并 | 改动记录 |
| 主题 | 新建 → 使用中 → 改名 / 合并进另一个 / 删除；删除时条目不受影响，主题页进回收站 | 回收站里的主题页 |
| 主题页 | 空白 → 有草稿 → 有内容；每次接受都写改动记录；能看历史、回到任一次 | 文件本身 |
| 卡片 | 新建 → 编辑 → 删除，进回收站 | 回收站 |
| 画布 | 新建 → 摆放 → 删除；只删位置，不删条目 | 无 |
| 获取插件 | 没装 → 已装 → 有新版本 → 已更新；来源撤下后「已撤下，还能用但不再更新」；停用；卸载；健康：正常 / 最近失败（原因）/ 平台改版后不可用 | 已收下的条目不受影响 |
| 跟着收 | 开着 → 暂停（用户）；平台限频时自动退避，写「抖音限制了频率，6 小时后再试」；要重新登录或获取插件不可用时停下并写原因；删除订阅不删已收下的 | 订阅记录 |
| 导入 | 扫描 → 预览（新的、已有的、能补全的）→ 导入中，限速 → 暂停 → 继续 → 完成，写结果与失败原因 | 导入记录 |
| 改动提议 | 提出 → 全部接受 / 部分接受 / 不要 → 可整批撤销；不作废，不计数、不提醒 | 改动记录 |
| 回收站里的东西 | 进入 → 恢复 / 到期清除 / 立即清除；到期和立即清除都清干净 | 无 |
| 资料库 | 新建 → 打开 → 换位置 → 备份到 WebDAV、S3 或另一个文件夹 → 检查与修复 | 文件本身 |
| Agent 连接 | 没连 → 已连（Claude Code、Codex 的 MCP；ACP 会话）→ 断开；每次写入都记下是谁 | 改动记录 |

两条容易做错的：

- **改动提议不能变成待办。** 不显示「待确认」数量。提议只出现在发起它的地方，也就是 Agent 会话或 CLI，另外在改动记录页里能查到。
- **检查与修复按 ArchiveBox 的 rescan 语义。** 目录里有、索引里没有的当作新发现；身份冲突只报告，不覆盖；索引目录整个删掉也能重建。见调研 [01 启示 3](research/01-comparable-products.md#4-对歇存的启示)。

在主题页上点「起草这一页」，主题页就是发起的地方，提议直接显示在这一页上。

<a id="6-不做"></a>
<a id="9-不做"></a>
## 9. 不做

- 云账号、协作、分享、推荐、社交；通知、提醒、复习、打卡、未读数；应用里自建的聊天助手。
- 内核和官方组织里的平台获取代码；宿主自己代装根证书、向别的进程注入、解密平台客户端的数据。读本机客户端数据的插件你可以自己装，放在单独的组织（[7.2](#72-获取插件)）；读你自己浏览器里你选的那个站点的 cookie 不在「不做」里。
- 通用笔记软件：只有记一句、卡片、主题页、成稿几处能写，长篇写作交给 Obsidian 等。
- 替你自动分类或删除；批量收别人的账号做对标分析。
- 拦你刷，替你过滤外面的信息。本产品只管你已经收下的。

刻意不存在的设置：通知开关、每日回顾时间、全部标为已读、连续天数和目标、自动删除很久没看的、自动分类直接生效、允许 Agent 删除。

<a id="7-成功标准"></a>
<a id="10-成功标准"></a>
## 10. 成功标准

- 找回率：搜索后 60 秒内打开某一条的比例。
- 保存摩擦：从按下到「收下了」的时间；要多输入一步的占比，目标是 0。
- 保险赔付率：原帖已经没了、本机还能读的条目占比，按平台分。
- 回访价值：收下 7 天后被打开过的比例。
- 不追求：日活、收下的总数、使用时长。

这些数字只在本机算，开发时自测用，不进界面，也不发出这台电脑。

<a id="9-风险"></a>
<a id="11-风险"></a>
## 11. 风险

| 风险 | 怎么应对 |
|---|---|
| 平台改版，插件失效 | 插件外置，按你排的顺序换下一个；原样留着 |
| 维护者收到律师函 | 函件发给维护者（[调研 06](research/06-platform-access-and-account-risk.md#163-下架停更与法律风险)）。例如 jackwener/wx-cli 因腾讯方面的 DMCA 通知，2026-07-15 起被 GitHub 屏蔽（[通知](https://github.com/github/dmca/blob/master/2026/07/2026-07-13-wechat.md)，2026-07-13；[调研 11](research/11-subscriptions-compat-and-wx-cli.md#1-wx-cli)）。应对：内核和官方组织里没有平台获取逻辑；七层都收，一个插件一个仓库，一次通知只波及那个仓库和它的 fork；client-hook 单独一个组织，GitHub 按 [DMCA 政策 F 节](https://github.com/github/site-policy/blob/main/Policies/content-removal-policies/dmca-takedown-policy.md)停用多次侵权的账号时，主组织不受牵连 |
| 平台账号受限 | 后果由你担，添加插件来源时确认一次声明；节奏上限；不要账号能取的不带账号 |
| 本机算力不够 | 识别能选本机或云端，第一次打开时说清 |
| 地图变成一团乱麻 | 位置稳定、语义缩放、不整体重排 |
| feed 把地图淹掉 | 按订阅设置：只收你挑的，或只收命中关注的 |
