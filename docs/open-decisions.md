3. **[P9](#7-获取与插件) 首批平台**（并 [P10](#7-获取与插件) 电脑端视觉层、[P18](#7-获取与插件) 安卓做到哪、[C3](#5-收下与入口) 合并转发）：要你说最常用的三到五个平台、打算在哪个 macOS 和微信版本上用，再看一眼 Mac 微信的视频号里有没有「赞和收藏」；决定获取方式组织的第一批仓库，以及宿主要不要先做 adb 管理。
4. **[P4](#7-获取与插件) 和 [P16](#7-获取与插件) 默认用不用账号**：两条建议方向相反，合成一问：能不登录就不登录，还是登录过就带上；[插件协议 §3.1](plugin-protocol.md#31-运行器与节奏) 的默认顺序和 [§0.4](plugin-protocol.md#04-需要同步的文档) 的两个默认值等它。
5. **[P7](#7-获取与插件) 复用日常浏览器时怎么拿登录态**：决定宿主读不读浏览器的 cookie 库、PRD「不做」一节那句怎么改；Windows 上 Chrome 的应用绑定加密可能让这条路读不到（推断，待核实）。
6. **[P19](#7-获取与插件) 视觉层调用能不能自己跑**：决定运行器怎么排占屏幕、剪贴板和手机的调用，跟着收、批量导入能不能带上视觉层插件。
7. **[O2](#13-开源与发布) 哪些文档公开**（并 O7 的分组、P13 的链接目标）：决定 [附录 A](plugin-protocol.md#附录-a-声明模板) 的声明和添加来源确认框里风险证据链到哪；只写取法的文档也收到过律师函（[06 §16.3](research/06-platform-access-and-account-risk.md#163-下架停更与法律风险)）。
8. **[R1](#12-声明与责任) 声明定稿**（并 R8、R9、R4）：风险设计的最后一块；只在公开前要，草稿先用占位，不挡写插件。
