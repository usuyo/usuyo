## 0. 怎么读

这份文档把 PRD 里抽象的词落成具体的对象、动作、文件和界面文案。写着「建议」的是我的提议；写着「待定 Dn」的需要你拍板，汇总在 [§12](#12-待决问题)。

<a id="1-一条视频从收下到放下"></a>
## 1. 一条视频从收下到放下

场景：周三晚上在抖音刷到一条 4 分钟的手冲咖啡教学，讲了水温和注水节奏。

| 阶段 | 用户做了什么 | 界面上看到什么 | 磁盘上发生什么 |
|---|---|---|---|
| 收下 | 复制分享链接，在电脑上按全局快捷键，粘贴，回车 | 浮层显示「收下了」，一秒后消失 | 新建 `items/2026/10/douyin-7f3a2c1e-k9x2/`，写入只有链接的 `manifest.json`，排队一个获取任务 |
| 获取 | 不用做什么 | 卡片从「只有链接」变成封面和标题 | 抖音的获取方式把页面数据和视频存进 `raw/s1/`；`content.md` 写入标题和描述 |
| 变成文字 | 不用做什么；默认等接上电源、电脑空闲时做 | 条目页多出「口播文字」「画面」两栏 | `derived/asr.vtt` 带时间点的口播；`images/keyframes/` 场景切换处的画面；`derived/ocr/` 画面里的字 |
| 找回 | 两个月后搜「水温 92」 | 结果写着「口播 01:42」，点开后视频从 01:42 开始播 | 只读索引 |
| 记一句 | 看完，在底部点「记一句」，写「92 度，闷蒸 30 秒」 | 条目上出现这句话 | `notes.md` 头部的 `takeaway` |
| 汇总 | 搜「手冲」，全选 23 条，点「放进主题」，新建「手冲咖啡」；在主题页点「起草这一页」 | 右侧出现一份草稿，每段标着出自哪几条；逐段点「接受」 | `topics/手冲咖啡.md`：头部列出 23 个成员，正文里每处引用带原话和时间点 |
| 放下 | 主题页底部点「这一页够用了」，选「来源都只留文字」 | 确认框：「删掉 23 个视频，腾出 4.1 GB。文字稿、画面缩略图和这一页都留着。视频 30 天内能从回收站恢复。」 | 23 个视频移进 `.trash/`；各条目变成只留文字；改动记录写一整批，可一次撤销 |

结果：23 条进来，留下一页。以后要用这件事就打开这一页；要回到原话，引用里就有。

<a id="2-主循环"></a>
## 2. 主循环

收下 → 变成文字 → 找回 → 汇总成一页 → 放下

- [PRD §6](PRD.md#6-主循环和一个例子) 的六步不变，其中「提炼」具体为「汇总成一页」。
- 「变少」的度量是多条进、一页出。建议在 [PRD §10](PRD.md#10-成功标准) 加一条：被主题页引用之后放下的来源占比。只在本机统计，不上报，不出现在主界面。
- 每一步都可以停在那里。只收下、从不整理，是正常用法；不存在「没整理完」。

<a id="4-文案规则"></a>
## 4. 文案规则

1. 按钮写「动词 + 对象」，有后果就写后果：「删掉这条（30 天内能恢复）」。不写「放下」「处理」「确定」。
2. 状态写事实，不写评价：「视频没存下来：平台没提供原文件」，不写「部分完整」。
3. 数字只描述这一次操作的结果：「删掉 23 个视频，腾出 4.1 GB」可以。描述积压的数字不出现：没有「还有 128 条」。
4. 「收藏」只用来指平台上的收藏夹，比如「抖音收藏夹」，不指 usuyo 里的动作。
5. 下表左列的词不出现在界面上：

| 不说 | 改说 |
|---|---|
| 收藏（指 usuyo 的动作时） | 收下、存着 |
| 待办、待整理、未读、已消化 | 不出现 |
| 完整度、部分完整 | 说缺什么 |
| 适配器 | 获取方式 |
| 变更集 | 改动提议 |
| 提炼 | 起草、汇总成一页 |
| 瘦身 | 只留文字 |
| 同步 | 跟着收 |
| 放下 | 具体动作名，见 [§5.2](#52-六个动作) |

6. 多语言：消息 id 用英文点分，例如 `item.keepText.confirm`；简体中文是源语言，English 必须带同样的后果信息；不拼接句子；数字、日期、文件大小用 `Intl` 格式化。
7. 不写「破解 / 去水印 / 绕过」，沿用 CLAUDE.md 的约定。

<a id="5-放下"></a>
## 5. 放下

**已作废（2026-10-28）。** 本节保留作记录。删掉和回收站暂按普通操作保留；「只留文字」暂按存储设置里的一个选项处理，两者都待确认。

放下是一组让存的东西变少、变轻的动作。每个动作都是用户在某一刻主动做的一件事，做完就结束，不留下「还没放下」的状态。

<a id="51-不制造压力的四条检验"></a>
### 5.1 不制造压力的四条检验

任何和放下有关的界面都要同时满足：

1. 只由用户的动作打开：看完一条时的底部操作栏、主题页底部、多选菜单、设置里的存储页。从不弹出、提醒、定时。
2. 不计数剩下的，只说这一次会发生什么。
3. 每个按钮写清后果和能不能撤回。
4. 没有「没放下」这一状态，任何地方都不按「放下了多少」排名或显示进度。

<a id="52-六个动作"></a>
### 5.2 六个动作

| 按钮 | 发生什么 | 能撤回吗 | 谁能发起 |
|---|---|---|---|
| 记一句 | 在 `notes.md` 头部写 `takeaway`，条目别的不变 | 能，随时改 | 用户；Agent 只能提议 |
| 只留文字 | 视频和原图移进回收站；留下 `content.md`、口播文字、图里的字、画面缩略图、原始页面数据；条目标为只留文字 | 30 天内从回收站恢复；之后只能「重新获取」，前提是原帖还在 | 只有用户 |
| 删掉 | 整个条目目录移进回收站，留下删除记录 | 30 天内恢复 | 只有用户 |
| 记一句再删掉 | 上面两步合在一个对话框里 | 同「删掉」 | 只有用户 |
| 这一页够用了 | 对一个主题的全部来源，批量「只留文字」或「删掉」；主题页留着 | 同上，整批一次撤销 | 只有用户 |
| 彻底忘掉 | 连删除记录也删掉 | 不能；对话框写明「以后跟着收可能会再收下它」 | 只有用户 |

在平台上取消收藏是第七个候选动作，见待定 D3。

「只留文字」和 [PRD §4](PRD.md#4-原则) 原则 2「raw 永远保留」字面冲突。建议把原则改成：机器永不改写或删除 raw；只有用户执行「只留文字」或「删掉」时才移走，并且先进回收站。见待定 D9。

<a id="53-从哪里发起"></a>
### 5.3 从哪里发起

- **条目页底部操作栏。** 一直在，不弹出：「记一句」「放进主题」「只留文字」「删掉」。
- **主题页底部。** 「这一页够用了」。
- **任意列表多选后。** 「只留文字」「删掉」。
- **设置 › 存储。** 显示视频和图片各占多少空间，可按主题、平台、类型批量「只留文字」。
- **翻翻很久没打开的，待定 D8。** 放在设置 › 存储下面。每次随机给 12 条超过 180 天没打开的，按钮「再换一批」，不显示总数。每张卡片上有「记一句」「只留文字」「删掉」「留着」。

<a id="54-边界情况"></a>
### 5.4 边界情况

| 情况 | 怎么处理 |
|---|---|
| 删掉之后，跟着收又遇到同一条 | 按身份查删除记录，跳过；只在这个订阅的记录里写一行「跳过 1 条：10 月 20 日删掉过」 |
| 删掉之后，用户自己又粘贴同一个链接 | 浮层写「10 月 20 日删掉过这条，当时记的一句是：……」，按钮「重新收下」「算了」；30 天内直接从回收站恢复，之后重新获取 |
| 被主题页引用的来源被删掉并清除 | 引用里存着原话、位置、条目 ID、标题和日期，这一页照常可读；引用处显示「来源已删掉（10 月 20 日）」 |
| 口播还没转成文字就想「只留文字」 | 按钮不可点，写原因「口播还没转成文字，现在删视频就只剩标题了」，旁边给「先转文字」；转写失败时写失败原因和「重试」 |
| 一条同时在两个主题里，在其中一个点「这一页够用了」 | 确认框写「其中 2 条也在『意式』主题里，那边也会变成只留文字」，可以先去掉这几条再执行 |
| Agent 提议给回收站里的条目加标签 | 这一处应用失败并写原因，同一批的其他改动照常生效 |
| 回收站到期清除 | 这是产品里唯一由系统发起的删除。设置可选 30 天、90 天、一直保留；清除前不通知，清除后改动记录里留一行 |
| 主题页本身被删掉 | 主题页进回收站，条目不受影响；成员列表在主题页文件里，恢复主题页就恢复了主题 |

<a id="6-知识层"></a>
## 6. 知识层

| 东西 | 谁写 | 存在哪 | 机器能改吗 |
|---|---|---|---|
| AI 摘要 | 模型，本机或云端，可以关 | `derived/summary.md`，记着模型和时间 | 能重算覆盖；界面标「AI 摘要」 |
| 记一句 | 用户；Agent 只能提议 | `notes.md` 头部 `takeaway` | 不能 |
| 主题页 | 用户；模型或 Agent 只能起草 | `topics/<slug>.md` | 不能改用户接受过的文字 |
| 卡片 | 用户 | `cards/<id>.md`，待定 D5 | 不能 |

规则：

1. **草稿只以改动提议出现。** 来源有两种：设置里配置的模型跑的后台任务，或用户自己的 Agent 通过 MCP / ACP。用户逐段接受、改了再接受，或不要。
2. **新条目加入主题，不改主题页。** 主题页上有「用 10 月 20 日之后加入的条目起草补充」，日期由用户选。
3. **引用自带原话。** 每处引用存条目 ID、位置（段落、图片区域或时间点）、原话、标题、日期。来源删掉之后这一页仍然完整。具体格式交给 SPEC，要求 Obsidian 打开时可读。
4. **主题页是普通 Markdown。** 头部 YAML 写标题、成员、创建和修改时间。可以在 Obsidian 里打开和编辑，外部改过之后 usuyo 重新读取。
5. **对资料库提问不在 usuyo 里做。** 没有内置聊天；用自己的 Agent 通过 MCP 搜和读。ACP 会话要不要显示在 usuyo 里，见待定 D4。
6. **用到模型的设置都写明去向。** 每一项写清内容会不会离开这台电脑、发到哪里。

<a id="7-生命周期"></a>
## 7. 生命周期

<a id="71-条目"></a>
### 7.1 条目

条目有四个互不影响的维度：

| 维度 | 取值 | 怎么变 | 界面怎么说 |
|---|---|---|---|
| 存下了多少 | 只有链接 → 部分 → 都存好了 | 只升不降；新快照更完整时升级 | 「只有链接」「缺视频：原因」「都存好了」 |
| 处理进度 | 每个任务单独算，见 [§7.2](#72-处理任务) | 后台任务推进 | 「口播转文字：等接上电源」 |
| 存在 | 正常 → 只留文字 → 在回收站 → 已清除，留删除记录 | 只有用户触发，到期清除除外 | 「只留文字（10 月 20 日）」 |
| 私密 | 开 / 关 | 用户 | 私密的条目不给 Agent，不进导出 |

<a id="72-处理任务"></a>
### 7.2 处理任务

任务种类：获取、规范化、图里的字、口播文字、关键帧、画面描述、AI 摘要、向量。

| 状态 | 进入 | 离开 | 界面怎么说 |
|---|---|---|---|
| 排队 | 收下或设置打开 | 轮到它 | 不显示 |
| 等条件 | 设置要求接电且空闲 | 条件满足 | 「等接上电源再做」 |
| 在做 | 开始执行 | 完成或失败 | 「正在把口播转成文字」 |
| 好了 | 成功 | 用户点「重做」 | 不显示 |
| 失败 | 出错；自动重试，间隔加倍，最多 3 次 | 用户点「重试」 | 写具体原因：「视频文件损坏，无法读取音轨」 |
| 关了 | 设置里关掉 | 设置打开 | 「口播转文字已关闭（设置 › 变成文字）」 |

设置从关改成开时只对新收下的生效；对已有的提供「对已有的也做一遍」。

<a id="73-其他对象"></a>
### 7.3 其他对象

| 对象 | 状态与转换 | 结束时留下什么 |
|---|---|---|
| 快照 | 获取中 → 存好 / 失败；只增不改；「只留文字」时其中的媒体文件移走 | 原始页面数据 |
| 标签 | 平台带的不可改；建议的点了才变成我的，忽略过的不再建议；我的可加、删、改名、合并 | 改动记录 |
| 主题 | 新建 → 使用中 → 改名 / 合并进另一个 / 删除；删除时条目不受影响，主题页进回收站 | 回收站里的主题页 |
| 主题页 | 空白 → 有草稿 → 有内容；每次接受都写改动记录；能看历史、回到任一次 | 文件本身 |
| 卡片 | 新建 → 编辑 → 删除，进回收站 | 回收站 |
| 画布 | 新建 → 摆放 → 删除；只删位置，不删条目 | 无 |
| 获取方式 | 没装 → 已装 → 有新版本 → 已更新；来源撤下后「已撤下，还能用但不再更新」；停用；卸载；健康：正常 / 最近失败（原因）/ 平台改版后不可用 | 已收下的条目不受影响 |
| 跟着收 | 开着 → 暂停（用户）；平台限频时自动退避，写「抖音限制了频率，6 小时后再试」；要重新登录或获取方式不可用时停下并写原因；删除订阅不删已收下的 | 订阅记录 |
| 导入 | 扫描 → 预览（新的、已有的、能补全的）→ 导入中，限速 → 暂停 → 继续 → 完成，写结果与失败原因 | 导入记录 |
| 改动提议 | 提出 → 全部接受 / 部分接受 / 不要 → 可整批撤销；7 天没处理就作废，不提醒 | 改动记录 |
| 回收站里的东西 | 进入 → 恢复 / 到期清除 / 立即清除 | 删除记录 |
| 删除记录 | 产生 → 重新收下时删除 / 彻底忘掉 | 无 |
| 资料库 | 新建 → 打开 → 换位置 → 备份到 WebDAV、S3 或另一个文件夹 → 检查与修复 | 文件本身 |
| Agent 连接 | 没连 → 已连（Claude Code、Codex 的 MCP；ACP 会话）→ 断开；每次写入都记下是谁 | 改动记录 |

两条容易做错的：

- **改动提议不能变成待办。** 不显示「待确认」数量。提议只出现在发起它的地方，也就是 Agent 会话或 CLI，另外在改动记录页里能查到。
- **检查与修复按 ArchiveBox 的 rescan 语义。** 目录里有、索引里没有的当作新发现；身份冲突只报告，不覆盖；索引目录整个删掉也能重建。见调研 [01 启示 3](research/01-comparable-products.md#4-对歇存的启示)。

<a id="9-产品边界"></a>
## 9. 产品边界

**做：**

- 多入口收下：粘贴、拖入、全局快捷键、浏览器扩展、手机投递、导入、跟着收、CLI、MCP、本地接口
- 全部变成文字：正文、图里的字、口播、关键帧、可选的画面描述
- 找回：全文、拼音、二字词、语义相近；按平台、类型、时间、命中层筛选
- 阅读与划线：在原文和口播文字里划线，划下的句子可以引用进主题页
- 整理：标签、主题、画布、多种视图
- 知识层：AI 摘要、记一句、主题页、卡片
- 放下：[§5.2](#52-六个动作) 的六个动作
- Agent：MCP、ACP、CLI、Skill 文件、本地接口
- 存储：本地目录为真相，可备份到 WebDAV、S3 或文件夹
- 迁出：Markdown 本身就是导出；另外提供 Netscape HTML 和 CSV 链接导出
- 多语言：简体中文、English

**不做：**

- 云账号、协作、分享、推荐、社交
- 内置任何平台的获取代码
- 通知、提醒、复习、打卡、未读
- 应用内自建的聊天助手
- 通用笔记软件。只有记一句、卡片、主题页三处可写，长篇写作交给 Obsidian 等
- 替用户自动分类或删除

**待定：** 见 [§12](#12-待决问题)。

## 11. 参考：看看收藏

[看看收藏](https://github.com/feitangyuan/kankan-shoucang)是一个只做小红书、只跑在 macOS 上的本地收藏工具，AGPL-3.0。

可以直接吸收的：

- **匿名单条获取。** 不带 Cookie、自报身份、失败时不回退到登录着的浏览器。这可以作为获取方式的一个信任等级「不需要登录」写进协议。
- **扩展只申请本地回环地址的权限。** usuyo 的浏览器扩展照此要求。
- **两个只读 MCP 工具。** 这是 Agent 接口的下限，usuyo 在它之上加了改动提议和撤销。

usuyo 不同的地方：

- 它的整理台按 9 个固定类目自动分堆，分不出就放进「待分类」。这正是 usuyo 要避免的「没整理」状态。usuyo 把整理台当成视图之一，堆由用户的标签或主题决定。
- 它的数据是一个 `notes.json`；usuyo 每条一个目录，文件即真相，跨平台。
- 它明确不做知识库；usuyo 要做主题页。

<a id="12-待决问题"></a>
## 12. 待决问题

按影响面排序。

| 编号 | 问题 | 建议 | 影响 |
|---|---|---|---|
| D1 | 知识的单位是什么 | 主题页是单位；条目是证据，记一句是每条的收获；机器只通过改动提议起草 | 文件结构、主题页界面、AI 设置、「这一页够用了」 |
| D2 | 打开 usuyo 先看到什么 | 搜索框，下面一行「最近收下」，再下面是用户选的默认视图；不做信息流 | 主窗口布局，前端设计的第一张图 |
| D3 | 要不要在平台上取消收藏 | 先不做。获取方式可以声明这个能力，内核留接口，默认关，每次批量执行前确认。风险：这是对用户平台账号的写操作，可能触发风控 | 适配器协议、放下动作 |
| D4 | ACP 会话要不要显示在 usuyo 窗口里 | 只显示改动提议和权限请求，不显示对话本身；对话留在用户自己的 Agent 里 | 要不要聊天界面，以及「不自建聊天助手」的边界 |
| D5 | 卡片，即原来的「念头」，要不要单独存在 | 保留，作为画布上的自由文字；否则画布上只能摆条目 | 文件布局、画布 |
| D6 | 注意力状态是否换成事实 | 取消四种状态，只记发生过的事 | manifest、画布 |
| D7 | 一个资料库几个画布 | 多个；每个主题可以有自己的画布，另有一个总画布 | 画布文件布局 |
| D8 | 要不要「翻翻很久没打开的」 | 要，放在设置 › 存储下面，只在用户点开时出现 | 放下的入口 |
| D9 | 原则 2 怎么改措辞 | 机器永不改写或删除 raw；只有用户执行「只留文字」或「删掉」时才移走，并先进回收站 | CLAUDE.md、PRD |
| D10 | 手机上能做什么 | 先只做投递；查看留给以后的只读版 | 范围 |
